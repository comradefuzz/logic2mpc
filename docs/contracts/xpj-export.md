# Контракт экспортёра .xpj

Версия контракта 1 (равна `PLAN_VERSION` плана). Экспортёр строит проект MPC Live 2 (прошивка 3.10.0.49) из плана экспорта и папки сэмплов. Код: `logic2mpc/adapters/xpj.py`, `xpj_spec.py`, `mpcfile.py`. История решений: стори S-018.

## Вход

- **План** по JSON Schema `logic2mpc/spec/export-plan.schema.json`. Экспортёр читает только поля из схемы: `bpm`, секции (`name`, `start`, `bars`), группы (`name`) и фрагменты их дорожек (`name`, `file`, `ticks`, `lead`, `export`, `merged_into`, вхождения с `tick`, `gain`, `length`). Остальные поля плана (уверенность, происхождение, правила анализа, заметки) разрешены и не влияют на результат.
- **Папка сэмплов**: WAV по `file` каждого экспортируемого фрагмента.
- **Имя проекта, групп и секций**: кириллица транслитерируется. Имена фрагментов экспортёр не меняет: они идут в имя WAV на MPC, поэтому в плане они должны быть латиницей без разделителей пути. Имена групп после транслитерации должны быть уникальны и не равны HANDS.
- **Единицы**: тики PPQ 960, такт 4/4 равен 3840 тиков, длина сэмплов в кадрах.
- **Опция экспорта** `note_on_from`: доля такта (`2/4` по умолчанию), граница «длинного» образца для режима Note On (AN-068). Не часть плана, схему не меняет. Значение не больше 0 или не доля отклоняется `ValueError` до записи.
- Вход проверяется по схеме до записи. Несоответствие даёт `ContractError` (наследник `ValueError`). План другой версии отклоняется так же.

## Выход

- `<имя>.xpj` и папка `<имя>_[ProjectData]` рядом, с одним именем. В папке копии WAV сэмплов под именем `<имя фрагмента>.wav`.
- `export_project(plan, samples, out, name)` возвращает `ExportResult(path, losses)`. `write_project` возвращает только путь.
- Состав проекта: корень из десяти ключей, треки HANDS (пустой) и по одному на группу, по 128 пэдов, секвенция на секцию, в каждой по клипу на трек. Служебных треков нет.
- Mute group (`whichMuteGroup`) выбирает экспортёр (AN-069): фрагменты одной дорожки плана, оставшиеся отдельными, получают общий номер 1–32 внутри драм-трека, остальные 0.
- Режим пэда выбирает экспортёр: Note On (`triggerMode` 2) у образца длиннее порога, все вхождения которого звучат до конца своей секции, иначе One Shot (0).
- Сборка детерминирована: одинаковый вход даёт одинаковые байты.

## Отказы

До записи, ничего на диск не попадает: `ContractError` (вход не по схеме), `ValueError` (в группе больше 128 фрагментов, совпадают имена треков после транслитерации), `FileNotFoundError` (нет WAV).

## Потери

Список строк `losses`, экспортёр их не печатает:
- проект собран без служебных треков Out, Submix, Return (MPC-112), всегда;
- число образцов и вхождений, которые звучат за концом своей секции (One Shot);
- число дорожек, которым не хватило mute group (максимум 32 в драм-треке);
- число фрагментов, слитых в другие.

## Формат

Что пишется и какие значения у полей, определяют `docs/formats/mpc/export.tsv` и факты базы. Файлы `logic2mpc/spec/*.json` порождает `scripts/build_spec.py` из реестра и эталонов, экспортёр читает только их. Донорский проект не используется. Описание поставляется вместе с экспортёром.

## Импорты из ядра

Экспортёр не зависит от анализа сигнала, интерфейса, кэша и Logic. Из ядра он импортирует ровно это (список сверяет тест):

- `core.model`: BAR
- `core.names`: transliterate
- `core.plan`: Group, Occurrence, Plan, PlanPiece, is_exported, occurrences_of
- `core.sections`: Section, place

При выносе в отдельный проект эти имена заменяются тонкой моделью плана. Просмотр готового проекта (`xpj_view.py`) в контракт не входит.

## Версионирование

Версия растёт при изменении входа, выхода или состава описания формата. Описание формата при этом меняется только вместе с фактами базы.
