# Анализ дорожки

Раздел «Алгоритм» это эталон: что анализ должен делать и почему, независимо от кода. Правки анализа и тесты сверяются с ним. Остальные разделы описывают текущий код и список работ. История решений в [spikes.md](spikes.md), устройство файлов Logic и MPC в [formats/](formats/).

Цель анализа: по экспорту дорожки и данным проекта получить минимальный набор сэмплов, позиции нот на пэдах и отчёт об осознанных потерях. Это перевод, а не копия, см. принципы в CLAUDE.md.

## Как менять

1. Сначала меняется правило здесь, затем тест, затем код.
2. Правило со статусом `принято` меняется только решением пользователя.
3. Тест указывает номер правила в имени или описании. Правило без теста это пробел в проверке.
4. Ревью сверяет изменения с этим разделом. Расхождение кода с правилом исправляется или записывается в «Расхождения».

Статусы:

- `принято`: подтверждено пользователем.
- `проверено на нотах`: сверено с нотами проекта, звук и прослушивание не проверялись.
- `гипотеза`: выведено из данных, пользователь результат ещё не подтвердил.

## Алгоритм

### Вход

**AN-001. Источники.** `принято`. Звук берётся из экспорта, структура, ноты и темп из файла Logic. Темп по звуку не определяется. Сэмплы режутся из экспорта, а не из исходников.

**AN-002. Стеки.** `принято`. Файлы стеков в анализ не входят: их звук задвоит дочерние дорожки. Слияние группы это отдельное решение плана.

**AN-003. Выключенные регионы.** `принято`. Не участвуют в поиске повторов и попадают в отчёт. Дорожка только с выключенными регионами в проект не входит и названа в отчёте. Партии не теряются молча.

**AN-004. Ветка.** `гипотеза`. Дорожка с нотами идёт по ветке MIDI, дорожка с аудиорегионами по ветке аудио. Дорожек с тем и другим в Elated нет, такой случай не определён.

### Аудиодорожка

Смысл читается по регионам проекта. Правила применяются сверху вниз, срабатывает первое подходящее.

**AN-009. Склейка.** `принято`. Регионы из одного файла это один звук, если стоят встык на таймлайне, с зазором до 1/16 такта, и идут встык в файле: смещение второго равно смещению первого плюс длина. Фрагмент файла задают номер файла, смещение и длина, см. LOGIC-R-009. Пример: `RiseExcellent`, 0 и 614000, затем 614000 и 154000 кадров, один цельный райзер.

**AN-010. Удары.** `гипотеза`. Регионов больше одного, Loop нет, атак столько же с допуском 1.2 раза. Каждый регион это один звук, одинаковые сливаются в один сэмпл. Пример: `kick_nerve`, 320 регионов и 320 атак, один сэмпл.

**AN-015. Одинаковые звуки.** `принято`. Сначала данные проекта: фрагменты одного файла с одним смещением это один звук, фрагмент внутри другого тоже, если его длина не меньше 75% большего. Если фрагменты файла разные, сравнивается звук: форма волны (корреляция 0.97) либо спектр и огибающая первой секунды (0.98 и 0.8, сняты с Elated) при разнице длин не больше 25%, иначе это укороченный вариант, AN-041. Шумовые звуки по волне не совпадают никогда, критерий здесь слух. Примеры: `FillsBuildupSnare`, фрагмент 6000–96000 внутри 0–96000; `Audio 48`, 4 разных удара брейка, один сэмпл только по слуху.

**AN-011. Цельный звук.** `гипотеза`. Один регион без Loop: сэмпл целиком, не резать. Атаки здесь не считаются: на шумовых свипах детектор находит десятки ложных. Пример: `JAFUNK_110_fx_martian_downlifter_short`, один сэмпл.

**AN-012. Луп.** `гипотеза`. Loop включён на всех регионах дорожки: длина фрагмента равна длине лупа, каждый проход это вхождение. Период Loop в файле не найден, поэтому длина берётся из кадров исходника и округляется до 1, 2, 4, 8 или 16 тактов, см. LOGIC-044. Пример: `HH Meat`, 2 такта.

**AN-014. Звуки в регионах.** `принято`. Все регионы из одного файла без Loop, и каждый склеен по AN-009 или короче 4 тактов: каждый регион это один звук, одинаковые сливаются по AN-015. Примеры: `FillsBuildupSnare`, `RiseExcellent` с отдельным фрагментом на такте 57.

**AN-013. Всё остальное.** `принято`. Окна по сетке и сравнение звука, см. «Решение по дорожке». Проверено на `LD Saw Harm`, `Fill JaBouncy`, `HH Meat`, `Fire Glow` в S-009.

### MIDI-дорожка

**AN-020. Повторы ищутся по нотам.** `принято`. Звук для этого не годится: один синт на одних нотах звучит каждый раз по-разному. У `Bass Oliver` одинаковые окна дают корреляцию 0.25–0.6 и разницу около +5 дБ.

**AN-020a. Проходы.** `принято`. Сетка проходов идёт через всю партию от начала цикла в обе стороны: совпавшие проходы раньше начала тоже входят в цикл. Примеры: `AmbientPiano`, `InterestingSines`, один фрагмент.

**AN-021. Сначала регионы.** `проверено на нотах`. Регионы сравниваются по времени и высоте нот, без длины. Период это наименьшая длина из 1, 2, 4, 8 тактов, на которой не меньше 70% пар регионов на этом расстоянии совпадают, а совпавшие регионы составляют не меньше половины дорожки. Начало цикла стоит на сетке этой длины от начала песни, если там есть регион, иначе на первом повторяющемся регионе. Период и начало дальше используются в ядре нот, шаги 2 и 3 из AN-022. Примеры: `Bass Oliver`, `A B C` с шагом 8 тактов; `Fire Glow`, пара «вариативные 4 такта + неизменные 4 такта».

**AN-022. Затем ядро нот.** `проверено на нотах`. Запускается, если регионы длинные или все разные. Пример: `ARP - Altar`.

1. Для длин 1, 2, 4, 8 тактов и каждого сдвига по тактам проходы накладываются друг на друга. Время округляется до 1/64, скорость и длина не учитываются.
2. Ядро это ноты, которые есть хотя бы в половине проходов.
3. Проход входит в цикл, если содержит не меньше 70% ядра. Поэтому обрывы и лишние ноты не мешают.
4. Оценка длины: доля вошедших проходов, умноженная на долю всех нот, объяснённых ядром.
5. Берётся самая короткая длина с оценкой не ниже 90% от лучшей.

Попарное сравнение окон не подходит: у `Fire Glow` проходы с разными добавками похожи между собой на 0.63, хотя каждый содержит партию.

**AN-023. Нет цикла.** `принято`. Партия звучит один раз или оценка цикла ниже 0.6: каждый регион это фрагмент от своего начала до конца звука, не дальше следующего региона, пауза до первой ноты длиннее четверти в сэмпл не попадает. Регионы, совпавшие по времени и высоте нот не меньше чем на 90%, это один фрагмент, неточные совпадения указываются как заменённые. Нота раньше начала региона сдвигает начало фрагмента на границу такта, где она лежит. Фрагмент с одним вхождением (группа из одного региона) начинается от последней четверти не позже первой ноты (AN-067), а не от начала региона; группа из нескольких регионов начинается от начала региона или такта. Лимит AN-040 действует. Уверенность 0.3. Пример: `NormalReese`, 3 сэмпла.

**AN-024. Барабаны на MIDI.** `гипотеза`. Ноты лежат на стеке, звук в дочерних дорожках: ван-шоты вырезаются по нотам, по одному на высоту. Пример: `French Connection+` в Pyro. Экспорта нет, для Elated не нужно.

### Образец и вырезание

**AN-030. Образец.** `принято`. Берётся проход, где фраза сыграна целиком: звук доходит до конца не хуже остальных с точностью до доли. Среди них самый частый точный вариант, сравниваются время, высота и длина нот, наложение меняет вариант. Из него проход, за которым тот же вариант идёт сразу следом, иначе самый ранний. Пример: `Bass Oliver`, такт 17; такт 9 обрезан аранжировкой.

**AN-033. Недоигранный проход.** `принято`. Проход или удар, где звук кончается раньше образца больше чем на долю, получает короткую ноту и записывается в потери. Партия при этом остаётся в проекте. Пример: `Bass Oliver`, такты 9, 49, 97.

**AN-034. Проход вне сетки.** `проверено на нотах`. Если на другом такте ноты совпадают с образцом точно, вхождение ставится туда, а проходы и варианты, с которыми оно пересекается, снимаются и попадают в потери. Пример: `Lothar BM`, такт 69, один сэмпл.

**AN-031. Отбор по обработке.** `гипотеза`. Среди оставшихся берётся проход без обработки. Критерия пока нет.

**AN-032. Границы.** `гипотеза`. Такты переводятся в кадры, фрагмент режется от начала прохода до конца звука, не дальше длины цикла.

### Сколько оставить

**AN-040. Решительность.** `принято`. Один параметр определяет, сколько вариантов слить с основным, в крайнем правом положении минимум. В обычном положении не больше 4 фрагментов на дорожку. Для ветки MIDI шкала к параметру пока не привязана: проходы вне цикла становятся вариантами по частоте, что сверх лимита, попадает в потери.

**AN-041. Укороченные варианты.** `принято`. Остаются отдельными фрагментами, решение пользователя по `LD Saw Harm`.

**AN-042. Кейгруппа отложена.** `принято`. MIDI-партия экспортируется как обычный цикл, кейгруппу пользователь при желании собирает на MPC. Пример: `Bass Oliver`, луп 8 тактов.

### Края

**AN-050. Пометка.** `принято`. После первой итерации экспорта сэмпл, у которого начало или конец не в нуле, помечается в отчёте с указанием края. Не в нуле значит, что крайние 4 отсчёта громче −54 дБ: фрагмент, обрезанный по концу звука, кончается на пороге тишины −60 дБ и пометки не получает. Детектор щелчков и пороги слышимости не нужны.

**AN-051. Обработка по команде.** `принято`. Автоматически края не обрабатываются. Спад применяется по команде пользователя к началу и/или концу конкретного сэмпла и создаёт новую версию нарезки.

### Выход

**AN-060. Имена сэмплов.** `принято`. Имя файла сэмпла `КОД_ГРУППА_Имя_NN.wav`. `КОД` это три буквы песни из плана, `ГРУППА` две буквы (`DR`, `BS`, `SY`, `VX`, `FX`, `GT`), `Имя` очищено от паков, темпа, тональности и служебных слов и записано слитно латиницей, `NN` номер внутри имени. Пустое после очистки имя заменяется группой и номером дорожки: `DrTrk24`. Нота пишется в конец только если поле ноты в плане заполнено: `PYR_BS_Bass_01_C2`, сама она не определяется. Кириллица всегда транслитерируется. Автоматика предлагает черновик, в плане имя правится пользователем (AN-070). Код в [names.py](../logic2mpc/core/names.py).

**AN-061. Отчёт.** `принято`. Что выбрано, что отброшено, какие такты заменены, насколько решение уверенное. Проход цикла, отличный от образца по нотам, указывается как заменённый. Вариации, недоигранные лупы и разница тембра записываются как осознанные потери.

**AN-062. Версии.** `принято`. Нарезка это версия, новая не перезаписывает старую. Отказ записывается вместе с причиной: в `decide.py` это аргумент, в продукте команды пока нет.

**AN-063. Секции.** `принято`. Каждый маркер Logic это своя секвенция MPC с его именем и длиной до следующего маркера. Вхождение попадает в секцию, где начинается. Вхождение, которое звучит через границу, в следующей секции не повторяется и записывается в отчёт. Без маркеров секвенция одна.

**AN-064. Громкость нот.** `гипотеза`. У ударов громкость вхождения переводится в velocity, у остальных velocity 1: разница звука там не громкость, см. AN-020.

**AN-065. Позиция ноты.** `принято`. Каждое вхождение становится нотой на пэде в тике, где звучит начало образца в песне. Секция определяется по этому тику, нота на первой доле секции стоит в её начале. Сдвигов ради запасов и компенсаций нет.

**AN-066. Чистый старт.** `принято`. Образец ударного фрагмента (AN-010, AN-014) имеет чистый старт: начинается с начала звука, то есть с первого отсчёта выше порога тишины −60 дБ от начала региона, как конец звука определяется последним отсчётом выше того же порога. Запаса перед звуком нет, паузы в начале нет. Распространение на другие фрагменты определяет AN-067. Тик вхождения равен тику региона плюс слышимая пауза до начала звука.

**AN-067. Выбор начала образца без признаков лупа.** `гипотеза`. Признаки лупа: копии региона встык, включённая функция Loop. Фрагмент без них начинается одним из двух способов: **А** со звука (AN-066, тишины в начале нет, нота в тике звука) или **Б** от доли (последняя четверть такта не позже звука, перед звуком тишина, нота в тике доли). Выбор определяют три измеряемые величины, названия типов звука не участвуют:
- `L` длина фрагмента в долях такта;
- `S` число различных положений вхождений внутри доли (шаг 1/16);
- `p` наибольшая пауза от доли до звука среди вхождений, мс.

Утверждение: существует разделение по `L`, `S`, `p`, которое предсказывает выбор пользователя между А и Б точнее двух простых правил сравнения: «всегда А» и «по правилу, породившему фрагмент (AN-010, AN-011, AN-014)». Ожидаемая форма разделения: Б выбирается, когда `L` не меньше четверти такта, `S` равно 1 и `p` заметна; иначе А; при малой `p` варианты неразличимы. Значения порогов в утверждение не входят, их подбирают по данным.

В MIDI-ветке (AN-021, AN-022, AN-023) начало звука известно по включённым нотам: образец с одним вхождением начинается на последней четверти такта не позже первой включённой ноты окна, выключенные регионы не учитываются (AN-003). Образец с повторами цикла начинается от границы цикла. Реализовано для этой ветки (S-023), остальные ветки проверка по протоколу ниже.

Проверка: для каждого фрагмента без признаков лупа собираются оба варианта; пользователь, не зная значений `L`, `S`, `p`, выбирает А, Б или «без разницы» по двум критериям: игра с пэда и правка нот на сетке MPC. Нужно не меньше 30 фрагментов с `p` не меньше 20 мс из трёх проектов (Elated, Pyro, MONTERO), в каждой из двух групп (выбрано А, выбрано Б) не меньше 5. Подтверждается, если лучшее разделение по `L`, `S`, `p` совпадает с выбором не реже чем в 90% случаев и лучше обоих простых правил не менее чем на 10 процентных пунктов. Опровергается, если не достигается 90% или не превосходит простые правила; тогда нужен другой признак, и правило остаётся без изменения (А для всех, как в AN-066).

**AN-068. Режим пэда.** `гипотеза`. Пэд играется в режиме Note On (`triggerMode` 2), если его образец строго длиннее порога и все его вхождения звучат целиком до конца своей секции. Иначе One Shot (`triggerMode` 0): образец короче порога или хотя бы одно вхождение длиннее остатка секции и доигрывается за её концом. Порог это параметр экспорта `note_on_from`, доля такта, по умолчанию 2/4. Длина вхождения это недоигранная длина (AN-033) или длина образца, в вхождения входят слитые фрагменты (AN-070). Режим один на пэд.

**AN-069. Mute group.** `гипотеза`. Фрагменты одной дорожки Logic, оставшиеся в плане отдельными (два и больше экспортируемых, слитые и выключенные не считаются), получают общую mute group на пэдах: запуск одного обрывает остальные, как регионы одной дорожки в Logic. Группа действует внутри драм-трека (в нём 32 группы), нумерация идёт от 1 по порядку дорожек группы плана и в каждом драм-треке начинается заново. Фрагмент дорожки с одним образцом и дорожки сверх 32 остаются без группы (0), нехватка записывается в потери. Фрагменты разных дорожек друг друга не глушат.

**AN-072. Цвета.** `гипотеза`. Драм-треки красятся так же, как Live 2 красит новые треки: по кругу из 21 цвета (`55FF00`, `00FF80`, `00AAFF` и далее, MPC-R-014), трек номер n получает цвет `n mod 21`. Пэды Live 2 сам не красит (по умолчанию режим ALL PADS, пэды зелёные), поэтому раскраска пэдов решение проекта: у драм-трека с пэдами режим SINGLE PAD (`Universal` false), фрагменты одной дорожки Logic, оставшиеся отдельными, красятся одним цветом того же круга, разные дорожки по порядку разными, нумерация в каждом драм-треке от 0. Слитые и выключенные фрагменты цвет не берут, пустые пэды без цвета (0).

### Правки пользователя

**AN-070. Правки плана.** `гипотеза`. Пользователь правит план после анализа, каждая правка это решение с `origin: user`, результат новая версия (`AN-062`), прежняя не меняется и подтверждения не наследует.

- Фрагменты объединяются только внутри одной дорожки. Пользователь выбирает целевой фрагмент: его звук и имя остаются сэмплом, остальные не экспортируются (`merged_into`), но остаются в плане. Вхождения всех слитых фрагментов играет цель. Вхождение хранит позицию атаки, поэтому нота у цели ставится в тике начала звука цели (AN-065), сдвиг не нужен; у планов, сделанных с запасом (поле `lead` больше 0), нота стоит раньше атаки на этот запас. Разделение снимает объединение целиком.
- Группы переименовываются и объединяются, результат носит имя и код первой выбранной. После объединения групп, переноса дорожки и разделения фрагмента в группе не больше 128 экспортируемых фрагментов.
- Дорожка переносится между группами. Сэмплы получают код группы-получателя, имя и файл меняются вместе, номера внутри `(код, имя)` остаются уникальными. Сэмпл с именем не по правилу `КОД_ГРУППА_Имя_NN` не переименовывается, это записывается в журнал и отчёт. Дорожка, вынесенная в новую группу, наследует код прежней. Пустая группа не остаётся.
- Что объединено, куда перенесено и что переименовано, записывается в журнал плана и в отчёт (`AN-061`).

**AN-071. Группы по умолчанию.** `принято`. Группа плана это папка Logic (`AN-002`). Код группы выбирается по имени папки без учёта регистра и по началу слова: `drum`→`DR`, `bass`→`BS`, `synth`, `lead`, `key`→`SY`, `fx`→`FX`, `vocal`, `vox`→`VX`, `guitar`→`GT`. Прочее имя даёт первые две латинские буквы большими, недостающие добираются `X`. Дорожка вне папок Logic входит в группу «Прочее» с кодом `OT`, отказа нет. Способ экспорта группы `drum`. Код песни это три первые латинские буквы большими части имени проекта после ` - ` или всего имени. Код песни идёт в имена файлов и поэтому всегда три заглавные латинские буквы, иначе отказ. Папка Logic с именем «Прочее» сливается с этой группой. Код группы правится пользователем (`AN-070`): сэмплы группы переименовываются по тем же правилам, что при переносе дорожки.

## Примитивы

Код в [signal.py](../logic2mpc/core/signal.py) и [spikes/audio_analysis/analyze.py](../spikes/audio_analysis/analyze.py). Каждый отвечает на один вопрос, их можно менять по отдельности.

| Вопрос | Примитив | Как работает | Настройки |
|---|---|---|---|
| Где атаки? | `find_onsets`, `refine_onset` | `librosa.onset`, затем старт по первому отсчёту выше 10% пика рядом с кадром | `hop` 128, `LEAD_IN` 2048 |
| Где кончается звук? | `sound_end`, `active_span` | Последний отсчёт выше порога тишины | `SILENCE` −60 дБ |
| Одинаковы ли два удара и какой сдвиг? | `match` | Нормированная корреляция по модулю со сдвигом | `EVENT_MATCH` 0.97, `COMPARE_LIMIT` 1 с, `PRE_ROLL` 20 мс |
| Одинаковы ли два окна? | `same_window` | Корреляция каждого такта отдельно, со знаком, без сдвига | `WINDOW_MATCH` 0.98, `DECIMATE` 4 |
| Что считать хвостом? | `group_windows` | Короткий остаток в начале окна сразу за предыдущим | `TAIL_SHARE` 1/8 |
| С какой громкостью сработал сэмпл? | В `analyze_events`, `analyze_windows` | Проекция срабатывания на сэмпл | Нет |
| Что потеряно? | `residual_db` | Энергия разницы оригинала и обратной сборки к энергии оригинала | Пороги ниже |
| Партия монофоническая? | `polyphony` | Наибольшее число одновременных нот, только по MIDI | Нет |
| Какая нота базовая? | `analyze_notes` | Самая длинная из самых частых нот, звук мерится `librosa.yin` | `fmin` 30, `fmax` 2000 |

## Решение по дорожке

Код в [windows.py](../logic2mpc/core/windows.py), перенесён из `decide.py` без спадов, проверено на 4 дорожках одной песни, S-009. Реализует AN-013.

| Вопрос | Как отвечает | Настройки |
|---|---|---|
| Какие бывают фрагменты? | Окна от первого звучащего такта. Короткий звук сразу за окном это хвост предыдущего фрагмента | `WINDOW_BARS` 1, 2, 4, 8 |
| Насколько различаются два фрагмента? | Подбор громкости, затем худший кадр разницы к средней энергии кадра. Каждый фрагмент прореживается отдельно | `FRAME` 50 мс, `REDUCE` 4 |
| Какая шкала? | Решительность линейна по порогу в дБ, от −60 до +20. 0 дБ значит, что худший кадр разницы равен среднему кадру фрагмента | `FLOOR_DB`, `CEILING_DB` |
| Что сливается? | Дерево с полной связью, решительность выбирает уровень разреза | `DEFAULT` 0.775, порог +2 дБ |
| Какая длина фрагмента? | Среди делений не больше 4 фрагментов наименьшая сумма тактов, при равенстве меньше фрагментов. Считается при значении по умолчанию | `MAX_VARIANTS` 4 |
| Что, если таких делений нет? | Вердикт `uncut`, длина 8 тактов, от значения по умолчанию вправо один фрагмент | Нет |
| Какой образец? | Фрагмент, ближайший к остальным в группе | Нет |
| Насколько решение надёжно? | Уверенность по самой дальней паре группы | Нет |
| Что потеряно? | Покрытие: вхождения, которые образец передаёт с различием не выше −40 дБ и без потери хвоста. Остальные такты названы в отчёте | `CLEAN_DB` −40 |

Вердикты: `clean` всё покрыто точно, `lossy` есть потери, `uncut` дорожка чисто не режется.

## Как улучшать

1. Сначала пример: дорожка и такт, где анализ ошибается, запись в «Известные слабости».
2. Если меняется поведение, правка правила в «Алгоритм».
3. Синтетический тест, который воспроизводит проблему и падает.
4. Правка одного примитива. Остальные не трогать.
5. Прогон и сверка с эталоном. Ни одна дорожка не должна стать хуже, кроме случая, когда прошлый результат был ошибкой: это объясняется в стори.
6. Обновить настройки, эталон, слабости и «Расхождения». Новую дорожку добавлять в эталон с ожиданием, снятым независимо от анализа: из `ProjectData`, с экрана Logic или на слух.

Новые настройки и пороги попадают сюда вместе с причиной. Вывод о формате Logic оформляется реквестом в базу, а не записью здесь.
