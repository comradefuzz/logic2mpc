# Анализ дорожки

Раздел «Алгоритм» это эталон: что анализ должен делать и почему, независимо от кода. Правки анализа и тесты сверяются с ним. Остальные разделы описывают текущий код и список работ. История решений в [spikes.md](spikes.md), устройство файлов Logic и MPC в [formats/](formats/).

Цель анализа: по экспорту дорожки и данным проекта получить минимальный набор сэмплов, позиции нот на пэдах и отчёт об осознанных потерях. Это перевод, а не копия, см. принципы в CLAUDE.md.

## Как менять

1. Сначала меняется правило здесь, затем тест, затем код.
2. Правило со статусом `принято` меняется только решением пользователя.
3. Тест указывает номер правила в имени или описании. Правило без теста это пробел в проверке.
4. Ревью сверяет изменения с этим разделом. Расхождение кода с правилом исправляется или записывается в «Расхождения».

Статусы:

- `принято`: подтверждено пользователем.
- `проверено на нотах`: сверено с нотами проекта, звук и прослушивание не проверялись.
- `гипотеза`: выведено из данных, нарезка по правилу не запускалась.

## Алгоритм

### Вход

**AN-001. Источники.** `принято`. Звук берётся из экспорта, структура, ноты и темп из файла Logic. Темп по звуку не определяется. Сэмплы режутся из экспорта, а не из исходников.

**AN-002. Стеки.** `принято`. Файлы стеков в анализ не входят: их звук задвоит дочерние дорожки. Слияние группы это отдельное решение плана.

**AN-003. Выключенные регионы.** `принято`. Не участвуют в поиске повторов и попадают в отчёт. Партии не теряются молча.

**AN-004. Ветка.** `гипотеза`. Дорожка с нотами идёт по ветке MIDI, дорожка с аудиорегионами по ветке аудио. Дорожек с тем и другим в Elated нет, такой случай не определён.

### Аудиодорожка

Смысл читается по регионам проекта. Правила применяются сверху вниз, срабатывает первое подходящее.

**AN-010. Удары.** `гипотеза`. Регионов больше одного, Loop нет, атак столько же с допуском 1.2 раза. Каждый регион это один звук, одинаковые сливаются в один сэмпл. Пример: `kick_nerve`, 320 регионов и 320 атак, один сэмпл.

**AN-011. Цельный звук.** `гипотеза`. Один регион без Loop: сэмпл целиком, не резать. Атаки здесь не считаются: на шумовых свипах детектор находит десятки ложных. Пример: `JAFUNK_110_fx_martian_downlifter_short`, один сэмпл.

**AN-012. Луп.** `гипотеза`. На регионе включён Loop: длина куска равна длине лупа. Пример: `HH Meat`, 2 такта.

**AN-013. Всё остальное.** `принято`. Окна по сетке и сравнение звука, см. «Решение по дорожке». Проверено на `LD Saw Harm`, `Fill JaBouncy`, `HH Meat`, `Fire Glow` в S-009.

### MIDI-дорожка

**AN-020. Повторы ищутся по нотам.** `принято`. Звук для этого не годится: один синт на одних нотах звучит каждый раз по-разному. У `Bass Oliver` одинаковые окна дают корреляцию 0.25–0.6 и разницу около +5 дБ.

**AN-021. Сначала регионы.** `проверено на нотах`. Регионы сравниваются по времени и высоте нот, без длины. Если типы регионов повторяются последовательностью, её период это цикл. Примеры: `Bass Oliver`, `A B C` с шагом 8 тактов; `Fire Glow`, пара «вариативные 4 такта + неизменные 4 такта».

**AN-022. Затем ядро нот.** `проверено на нотах`. Запускается, если регионы длинные или все разные. Пример: `ARP - Altar`.

1. Для длин 1, 2, 4, 8 тактов и каждого сдвига по тактам проходы накладываются друг на друга. Время округляется до 1/64, скорость и длина не учитываются.
2. Ядро это ноты, которые есть хотя бы в половине проходов.
3. Проход входит в цикл, если содержит не меньше 70% ядра. Поэтому обрывы и лишние ноты не мешают.
4. Оценка длины: доля вошедших проходов, умноженная на долю всех нот, объяснённых ядром.
5. Берётся самая короткая длина с оценкой не ниже 90% от лучшей.

Попарное сравнение окон не подходит: у `Fire Glow` проходы с разными добавками похожи между собой на 0.63, хотя каждый содержит партию.

**AN-023. Нет цикла.** `гипотеза`. Партия звучит один раз или повторов мало: кусок целиком с пометкой о низкой уверенности. Примеры: `DS_LENNO_lead_talkbox`, `Jupiter Duality`, `Hypa Saw`.

**AN-024. Барабаны на MIDI.** `гипотеза`. Ноты лежат на стеке, звук в дочерних дорожках: ван-шоты вырезаются по нотам, по одному на высоту. Пример: `French Connection+` в Pyro. Экспорта нет, для Elated не нужно.

### Образец и вырезание

**AN-030. Отбор по нотам.** `проверено на нотах`. Берётся самый частый вариант цикла без наложений других регионов. Пример: `Fire Glow`, пара `F` + `C`, такты 65 и 113, такт 49 отпадает из-за наложения региона `G`.

**AN-031. Отбор по звуку.** `гипотеза`. Среди оставшихся берётся проход без обработки. Критерия пока нет, до него берётся первый подходящий по нотам.

**AN-032. Границы.** `гипотеза`. Такты переводятся в кадры, кусок режется ровно по длине цикла.

### Сколько оставить

**AN-040. Решительность.** `принято`. Один параметр определяет, сколько вариантов слить с основным, в крайнем правом положении минимум. В обычном положении не больше 4 кусков на дорожку. Для ветки MIDI шкала к параметру пока не привязана.

**AN-041. Укороченные варианты.** `принято`. Остаются отдельными кусками, решение пользователя по `LD Saw Harm`.

**AN-042. Кейгруппа отложена.** `принято`. MIDI-партия экспортируется как обычный цикл, кейгруппу пользователь при желании собирает на MPC. Пример: `Bass Oliver`, луп 8 тактов.

### Края

**AN-050. Пометка.** `принято`. После первой итерации экспорта сэмпл, у которого начало или конец не в нуле, помечается в отчёте с указанием края. Детектор щелчков и пороги слышимости не нужны.

**AN-051. Обработка по команде.** `принято`. Автоматически края не обрабатываются. Спад применяется по команде пользователя к началу и/или концу конкретного сэмпла и создаёт новую версию нарезки.

### Выход

**AN-060. Сэмплы и ноты.** `гипотеза`. Сэмплы именуются по правилу из CLAUDE.md. Каждое вхождение становится нотой на пэде в своей позиции, для ударов громкость переводится в velocity.

**AN-061. Отчёт.** `принято`. Что выбрано, что отброшено, какие такты заменены, насколько решение уверенное. Вариации, недоигранные лупы и разница тембра записываются как осознанные потери.

**AN-062. Версии.** `принято`. Нарезка это версия, новая не перезаписывает старую, отказ записывается вместе с причиной.

## Расхождения

Где код отличается от алгоритма.

| Правило | Что в коде |
|---|---|
| AN-010–012 | `decide.py` режет все дорожки окнами, кик получает кусок на 8 тактов |
| AN-020–023 | `decide.py` сравнивает только звук, код поиска по нотам есть только в черновом прототипе |
| AN-050, AN-051 | `decide.py` ставит спад автоматически |
| AN-060 | В `decision.json` у вхождения нет громкости |

## Вход и выход кода

| Что | Откуда | Что содержит |
|---|---|---|
| Звук | Экспорт `NN_Имя.wav` | Стерео. Сравнение идёт по моно, среднему каналов |
| Сетка `Grid` | `probe.py positions` | Темп, начала регионов, конец Loop, ноты |
| Решение | `vN/decision.json`, `vN/report.md`, WAV | Группы, вхождения, вердикт, уверенность, покрытие |

## Примитивы

Код в [analyze.py](../spikes/audio_analysis/analyze.py). Каждый отвечает на один вопрос, их можно менять по отдельности.

| Вопрос | Примитив | Как работает | Настройки |
|---|---|---|---|
| Где атаки? | `find_onsets`, `refine_onset` | `librosa.onset`, затем старт по первому отсчёту выше 10% пика рядом с кадром | `hop` 128, `LEAD_IN` 2048 |
| Где кончается звук? | `sound_end`, `active_span` | Последний отсчёт выше порога тишины | `SILENCE` −60 дБ |
| Одинаковы ли два удара и какой сдвиг? | `match` | Нормированная корреляция по модулю со сдвигом | `EVENT_MATCH` 0.97, `COMPARE_LIMIT` 1 с, `PRE_ROLL` 20 мс |
| Одинаковы ли два окна? | `same_window` | Корреляция каждого такта отдельно, со знаком, без сдвига | `WINDOW_MATCH` 0.98, `DECIMATE` 4 |
| Что считать хвостом? | `group_windows` | Короткий остаток в начале окна сразу за предыдущим | `TAIL_SHARE` 1/8 |
| С какой громкостью сработал сэмпл? | В `analyze_events`, `analyze_windows` | Проекция срабатывания на сэмпл | Нет |
| Что потеряно? | `residual_db` | Энергия разницы оригинала и обратной сборки к энергии оригинала | Пороги ниже |
| Партия монофоническая? | `polyphony` | Наибольшее число одновременных нот, только по MIDI | Нет |
| Какая нота базовая? | `analyze_notes` | Самая длинная из самых частых нот, звук мерится `librosa.yin` | `fmin` 30, `fmax` 2000 |

## Решение по дорожке

Код в [decide.py](../spikes/audio_analysis/decide.py), проверено на 4 дорожках одной песни, S-009. Реализует AN-013.

| Вопрос | Как отвечает | Настройки |
|---|---|---|
| Какие бывают куски? | Окна от первого звучащего такта. Короткий звук сразу за окном это хвост предыдущего куска | `WINDOW_BARS` 1, 2, 4, 8 |
| Насколько различаются два куска? | Подбор громкости, затем худший кадр разницы к средней энергии кадра. Каждый кусок прореживается отдельно | `FRAME` 50 мс, `REDUCE` 4 |
| Какая шкала? | Решительность линейна по порогу в дБ, от −60 до +20. 0 дБ значит, что худший кадр разницы равен среднему кадру куска | `FLOOR_DB`, `CEILING_DB` |
| Что сливается? | Дерево с полной связью, решительность выбирает уровень разреза | `DEFAULT` 0.775, порог +2 дБ |
| Какая длина куска? | Среди делений не больше 4 кусков наименьшая сумма тактов, при равенстве меньше кусков. Считается при значении по умолчанию | `MAX_VARIANTS` 4 |
| Что, если таких делений нет? | Вердикт `uncut`, длина 8 тактов, от значения по умолчанию вправо один кусок | Нет |
| Какой образец? | Кусок, ближайший к остальным в группе | Нет |
| Насколько решение надёжно? | Уверенность по самой дальней паре группы | Нет |
| Что потеряно? | Покрытие: вхождения, которые образец передаёт с различием не выше −40 дБ и без потери хвоста. Остальные такты названы в отчёте | `CLEAN_DB` −40 |

Вердикты: `clean` всё покрыто точно, `lossy` есть потери, `uncut` дорожка чисто не режется.

Выход: папка `vN/` на запуск, WAV, `report.md`, `decision.json` со всеми группами и вхождениями. Отказ записывается аргументом `--refusal`.

## Известные слабости

| Слабость | Чем проявляется | Что проверить |
|---|---|---|
| Выбор длины в `decide.py` дробит цельный звук | На 8 дорожках с одним регионом от 2 до 4 кусков | Правила AN-010–012 |
| Ядро предпочитает короткую длину | Второй `Talk Box 1`: ноты дают 1 такт, регионы 8. `Ambient Piano`: 4 такта при шаге регионов 8. `ARP - Altar`: 0.88 на 4 тактах против 0.83 на 8 | Проверка на слух, правило выбора длины |
| Цикл не определён на редких партиях | `Reese` и `BL_Actually_Beautiful`: половина проходов, `Hypa Saw`: ни одного | Правило AN-023 |
| Обработка звука не видна по нотам | `Fire Glow`: образец выбран без учёта фильтра | Критерий для AN-031 |
| Стык лупа не проверен | Нет настоящих лупов с известным результатом | Прослушивание первых вырезанных лупов |
| Остаток усредняется по всей дорожке или окну | 49 мс с пиком −12.9 дБ в окне `LD Saw Harm` дают всего −31.9 дБ | Покадровый остаток по худшему кадру, 50 мс, один порог на все способы |
| Начало фраз `LD Saw Harm` | Такты 1, 17, 25, 65, 113 отличаются в начале куска и слиты при значении по умолчанию, такты 41, 57, 89, 105 совпали между собой | Проверка на слух |
| Шкала подобрана на одной песне | Значение 0.775 снято с 4 дорожек | Другие песни |
| У `uncut` нет промежуточных положений | `decide.py` на `Fire Glow`: 12 кусков, затем сразу 1 | Лучшее правило для дорожек без повторов |
| Хвост сравнивается только по длине | Другой хвост той же длины теряется без записи | Сравнение хвостов по содержимому |
| Низкое сходство не объясняется | Фильтр, фаза и разные ноты выглядят одинаково | Сравнение нот в окне и спектра |
| Сравнение окон без сдвига | Звук со сдвигом от сетки считается разным | Выравнивание корреляцией |
| Модуль в `match` | Удар в обратной полярности считается тем же звуком, `same_window` такой случай отличает | Корреляция со знаком |
| Сравнение окон идёт с прореживанием без фильтра | Верх спектра заменяется наложением частот | Прореживание с фильтром или сравнение без него |
| Сэмпл берётся из первого вхождения | Хвост предыдущего блока попадает в сэмпл | Выбор самого чистого вхождения |
| Громкость одна на срабатывание | Автоматизация внутри окна не учитывается | Огибающая громкости |
| Перекрытия не разбираются | Наложение звуков внутри дорожки уходит в остаток | Вычитание уже найденного сэмпла |

Стеки анализом не покрыты.

## Как улучшать

1. Сначала пример: дорожка и такт, где анализ ошибается, запись в «Известные слабости».
2. Если меняется поведение, правка правила в «Алгоритм».
3. Синтетический тест, который воспроизводит проблему и падает.
4. Правка одного примитива. Остальные не трогать.
5. Прогон и сверка с эталоном. Ни одна дорожка не должна стать хуже, кроме случая, когда прошлый результат был ошибкой: это объясняется в стори.
6. Обновить настройки, эталон, слабости и «Расхождения». Новую дорожку добавлять в эталон с ожиданием, снятым независимо от анализа: из `ProjectData`, с экрана Logic или на слух.

Новые настройки и пороги попадают сюда вместе с причиной. Вывод о формате Logic оформляется реквестом в базу, а не записью здесь.
