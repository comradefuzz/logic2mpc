# Анализ аудио: примитивы

Из чего строится анализ дорожки и как его улучшать. Код сейчас в [spikes/audio_analysis/analyze.py](../spikes/audio_analysis/analyze.py), история решений в разделе «Спайк 5» в [spikes.md](spikes.md). Устройство файлов Logic описано в [formats/](formats/), здесь только обработка звука.

Цель анализа: по экспорту дорожки и сетке проекта получить сэмплы с границами и срабатывания с позицией и громкостью, ничего не потеряв.

## Вход и выход

| Что | Откуда | Что содержит |
|---|---|---|
| Звук | Экспорт `NN_Имя.wav` | Стерео. Сравнение идёт по моно, среднему каналов |
| Сетка `Grid` | `probe.py positions` | Темп, начала регионов, конец Loop, ноты |
| `Analysis` | `analysis.json` | Режим, сэмплы, срабатывания, хвосты, остаток |

Темп не определяется по звуку, он берётся из проекта.

## Примитивы

Каждый отвечает на один вопрос, их можно менять по отдельности.

| Вопрос | Примитив | Как работает | Настройки |
|---|---|---|---|
| Где атаки? | `find_onsets`, `refine_onset` | `librosa.onset`, затем старт по первому отсчёту выше 10% пика рядом с кадром | `hop` 128, `LEAD_IN` 2048 |
| Где кончается звук? | `sound_end`, `active_span` | Последний отсчёт выше порога тишины | `SILENCE` −60 дБ |
| Одинаковы ли два удара и какой сдвиг? | `match` | Нормированная корреляция по модулю со сдвигом | `EVENT_MATCH` 0.97, `COMPARE_LIMIT` 1 с, `PRE_ROLL` 20 мс |
| Одинаковы ли два окна? | `same_window` | Корреляция каждого такта отдельно, со знаком, без сдвига | `WINDOW_MATCH` 0.98, `DECIMATE` 4 |
| На какие куски делится дорожка? | `group_windows`, `analyze_windows` | Окна по сетке, берётся длина с наименьшим числом разных кусков, при равенстве меньшая | `WINDOW_BARS` 1–16 |
| Что считать хвостом? | `group_windows` | Короткий остаток в начале окна сразу за предыдущим | `TAIL_SHARE` 1/8 |
| С какой громкостью сработал сэмпл? | В `analyze_events`, `analyze_windows` | Проекция срабатывания на сэмпл | Нет |
| Что потеряно? | `residual_db` | Энергия разницы оригинала и обратной сборки к энергии оригинала | Пороги ниже |
| Партия монофоническая? | `polyphony` | Наибольшее число одновременных нот, только по MIDI | Нет |
| Какая нота базовая? | `analyze_notes` | Самая длинная из самых частых нот, звук мерится `librosa.yin` | `fmin` 30, `fmax` 2000 |
| Какой режим? | `analyze` | См. ниже | `EVENT_RATIO` 1.2 |

## Решение по дорожке

Код в [decide.py](../spikes/audio_analysis/decide.py), проверено на 4 дорожках одной песни, S-009.

| Вопрос | Как отвечает | Настройки |
|---|---|---|
| Какие бывают куски? | Окна от первого звучащего такта. Короткий звук сразу за окном это хвост предыдущего куска | `WINDOW_BARS` 1, 2, 4, 8 |
| Насколько различаются два куска? | Подбор громкости, затем худший кадр разницы к средней энергии кадра. Каждый кусок прореживается отдельно | `FRAME` 50 мс, `REDUCE` 4 |
| Какая шкала? | Решительность линейна по порогу в дБ, от −60 до +20. 0 дБ значит, что худший кадр разницы равен среднему кадру куска | `FLOOR_DB`, `CEILING_DB` |
| Что сливается? | Дерево с полной связью, решительность выбирает уровень разреза | `DEFAULT` 0.775, порог +2 дБ |
| Какая длина куска? | Среди делений не больше 4 кусков наименьшая сумма тактов, при равенстве меньше кусков. Считается при значении по умолчанию | `MAX_VARIANTS` 4 |
| Что, если таких делений нет? | Вердикт `uncut`, длина 8 тактов, от значения по умолчанию вправо один кусок | Нет |
| Какой образец? | Кусок, ближайший к остальным в группе | Нет |
| Насколько решение надёжно? | Уверенность по самой дальней паре группы | Нет |
| Что потеряно? | Покрытие: вхождения, которые образец передаёт с различием не выше −40 дБ и без потери хвоста. Остальные такты названы в отчёте | `CLEAN_DB` −40 |

Укороченный вариант остаётся отдельным куском, решение пользователя по `LD Saw Harm`: третий и четвёртый файлы это начало первого, различие около −63 дБ.

Вердикты: `clean` всё покрыто точно, `lossy` есть потери, `uncut` дорожка чисто не режется.

Оборванный край WAV получает спад: 2 мс в начале, 10 мс в конце.

Выход: папка `vN/` на запуск, WAV, `report.md`, `decision.json` со всеми группами и вхождениями. Отказ записывается аргументом `--refusal`.

Режимы ниже описывают код S-008 и заменены этой схемой для дорожек, где режется звук. Дорожка из нот режется по звуку так же, начало берётся по первой ноте: `Fire Glow`. Кейгруппа и монофония пока только в `notes`.

- **`notes`:** у дорожки только ноты. Сейчас покрыт только частный случай, моно-партия под кейгруппу: проверка монофонии и выбор базовой ноты. Для партии с аккордами режим только сообщает полифонию, сэмплов и срабатываний не даёт.
- **`events`:** Loop нет, а атак столько же, сколько начал регионов, с допуском 1.2 раза. Каждый регион это один звук.
- **`windows`:** все остальные случаи. Повторы ищутся окнами по сетке.

## Пороги и эталон

Остаток показывает, что потеряно, и не является критерием готовности. Значения для спайка сняты с одной песни: `events` не выше −55 дБ, `windows` не выше −30 дБ.

Порог `windows` определяет одна дорожка, `LD Saw Harm`. Остальные дорожки этого режима проходят и −55 дБ.

Эталон качества, Elated 1, прогон `run.py`:

| Дорожка | Режим | Сэмплов | Срабатываний | Остаток, дБ |
|---|---|---|---|---|
| `snare_package` | events | 1 | 136 | −77.6 |
| `kick_nerve` | events | 1 | 320 | −82.4 |
| `Audio 48` | events | 4 | 68 | −62.3 |
| `KSHMR impact` | events | 1 | 7 | −58.3 |
| `HH Meat` | windows | 1 | 34 | −95.6 |
| `shs_roam_breaks` | windows | 2 | 6 | −84.2 |
| `LD Saw Harm` | windows | 4 | 12 | −32.3 |
| `Bass Oliver` | notes | нота 55, в звуке 30.83 | 425 нот | нет |

## Известные слабости

| Слабость | Чем проявляется | Что проверить |
|---|---|---|
| Остаток усредняется по всей дорожке или окну | 49 мс с пиком −12.9 дБ в окне `LD Saw Harm` дают всего −31.9 дБ | Покадровый остаток по худшему кадру, 50 мс, один порог на все режимы |
| Начало фраз `LD Saw Harm` | Такты 1, 17, 25, 65, 113 отличаются в начале куска и слиты при значении по умолчанию, такты 41, 57, 89, 105 совпали между собой | Проверка на слух |
| Шкала подобрана на одной песне | Значение 0.775 снято с 4 дорожек | Другие песни |
| У `uncut` нет промежуточных положений | `Fire Glow`: 12 кусков, затем сразу 1 | Лучшее правило для дорожек без повторов |
| Образец для `uncut` выбран без оценки музыкальности | `Fire Glow`: 28 пар из 66 упёрлись в потолок 20 дБ из-за отсутствия корреляции, такт 53 выбран в основном по тому, какие это пары | Проверка на слух, правило выбора фрагмента |
| Хвост сравнивается только по длине | Другой хвост той же длины теряется без записи | Сравнение хвостов по содержимому |
| Низкое сходство не объясняется | Фильтр, фаза и разные ноты выглядят одинаково | Сравнение нот в окне и спектра |
| Сравнение окон без сдвига | Звук со сдвигом от сетки считается разным | Выравнивание корреляцией |
| Модуль в `match` | Удар в обратной полярности считается тем же звуком, `same_window` такой случай отличает | Корреляция со знаком |
| Сравнение окон идёт с прореживанием без фильтра | Верх спектра заменяется наложением частот | Прореживание с фильтром или сравнение без него |
| Сэмпл берётся из первого вхождения | Хвост предыдущего блока попадает в сэмпл | Выбор самого чистого вхождения |
| Громкость одна на срабатывание | Автоматизация внутри окна не учитывается | Огибающая громкости |
| Перекрытия не разбираются | Наложение звуков внутри дорожки уходит в остаток | Вычитание уже найденного сэмпла |
| Корень измеряется по одной ноте | Отклонение до −0.19 полутона на низких частотах не объяснено | Медиана по нескольким нотам |
| Аккордовые партии не разбираются | Плаки и другие MIDI-партии с аккордами остаются без сэмплов | Ноты с одним началом это событие, одинаковый набор высот это кандидат на один сэмпл, сходство проверяется по звуку. Режим `notes` становится выбором между кейгруппой и событиями. На реальной дорожке не проверялось |

Стеки анализом не покрыты.

## Как улучшать

1. Сначала пример: дорожка и такт, где анализ ошибается, запись в «Известные слабости».
2. Синтетический тест в `test_analyze.py`, который воспроизводит проблему и падает.
3. Правка одного примитива. Остальные не трогать.
4. Прогон `run.py` и сверка с эталоном. Ни одна дорожка не должна стать хуже, кроме случая, когда прошлый результат был ошибкой: это объясняется в стори.
5. Обновить здесь настройки, эталон и слабости. Новую дорожку добавлять в эталон с ожиданием, снятым независимо от анализа: из `ProjectData`, с экрана Logic или на слух.

Новые настройки и пороги попадают сюда вместе с причиной. Вывод о формате Logic оформляется реквестом в базу, а не записью здесь.
