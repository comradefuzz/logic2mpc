## Спайк 1. Что читается из проекта Logic

Стори [S-001](../stories/S-001-logic-project-read.md). Инструмент: `spikes/logic_read/probe.py`, контрольный проект: [CHECKLIST.md](../spikes/logic_read/CHECKLIST.md).

### Решение

Статус: принято в S-001. Контрольный проект сошёлся, деревья стеков Pyro и Elated пользователь сверил с экраном Logic.

**Структуру и ноты берём из файла, звук из экспорта.**

- Из `.logicx`: дорожки, стеки, регионы с дорожками, ноты, темп, размер, маркеры. Про ноты и их оговорки см. спайк 3.
- MIDI-экспорт служит сверкой.
- Из экспорта аудио (спайк 2): сами звуки.

Папочная структура читается из файла, поэтому спайку 2 не нужно восстанавливать её по именам.

### Риск

Высокий на горизонте обновлений Logic: формат недокументирован, а размер записей и номера схем менялись между версиями. Поэтому чтение привязывается к версии файла. На неизвестной версии чтение должно останавливаться с понятным сообщением, а не выдавать догадку. Перед поддержкой новой версии Logic контрольный проект пересобирается и сверяется заново. Если чтение сломается, запасной путь это структура из имён экспорта.

### Проверено на

|---|---|---|---|
| Spike Control и три копии | 10.8.1 | `cb09` | 7 (копия 3 позже изменена в спайке 2, теперь 9) |
| Fuzz - Pyro | 10.8.1 | `cb09` | 135 |
| Fuzz - Elated | 10.8.1 | `cb09` | 66 |
| MONTERO (демо) | 10.7.0 | `c409` | 139 |

## Спайк 2. Автоэкспорт из Logic

Стори [S-002](../stories/S-002-logic-auto-export.md). Инструмент: `spikes/logic_export/match.py`, контрольный проект на Logic 10.8.1, два экспорта с одним набором настроек. Реальные проекты не экспортировались, поэтому время и поведение на большом проекте неизвестны.

### Решение

**Экспорт делает пользователь вручную, приложение проверяет результат.** Автозапуск в первую версию не входит.

- Официальной команды нет: в `LogicSuite.sdef` только `renderPreview`.
- Управление интерфейсом требует Accessibility и зависит от меню Logic. macOS не показала запрос разрешения, и пользователь решил не выдавать его вручную, поэтому скрипт `export_all.applescript` не запускался. Это черновик с известными слабостями, а не проверенный способ.
- Экспорт это один диалог на песню, и шаблон с настройками задаются вручную.

### Настройки

С этими значениями сделаны оба экспорта. Сравнения вариантов не было: влияние эффектов, фейдеров, хвоста и других значений `Range` не проверялось, это выбор по смыслу. На выбранных значениях старт звука и формат подтверждены.

| Поле | Значение |
|---|---|
| Range | `Trim Silence at File End` |
| Save Format, Bit Depth | WAVE, 24-bit |
| Bypass Effect Plug-ins | выкл. |
| Include Audio Tail | вкл. |
| Include Volume/Pan Automation | выкл. |
| Include Tempo Information | вкл. |
| Normalize | Off |
| Pattern | `Track Number`, `Custom` со значением `_`, `Track Name` |

Шаблон имён: `NN_Имя.wav`, без тега. Шаблон один на весь экспорт, а способ экспорта хранится в Export Plan. Сохраняется ли шаблон между экспортами, не проверялось.

### Что выгружается

См. LOGIC-085 и LOGIC-086 в [экспортах](formats/logic/exports.md).

### Следствия для продукта

- Файлы стеков нельзя брать вместе с дочерними дорожками: звук задвоится. Они годятся только для слияния группы, и там надо учитывать Mute.
- Mute дорожки `probe.py` пока не читает.
- Для проверки результата: нет файла у folder-стека или пустой дорожки это норма, нет файла у дорожки с регионами или у summing-стека это ошибка. Правило проверено на Audio и Software Instrument. Mute региона, Track Alternatives и take folders не проверялись, поэтому пока оно не гарантирует, что партии не теряются. `match.py` эти случаи ещё не различает.
- Кэш надо считать по чанку `data`, а не по файлу: при одинаковом звуке файлы различаются служебными чанками `bext`, `ResU`, `JUNK`. Из дорожек без правок звук отличается только у `CTRL_kick`, причина не выяснена: сравнивались два разных проекта, и в варианте на этой дорожке включён Mute. Повторного экспорта одного проекта не было.

## Спайк 5. Анализ реальных стемов

Стори [S-008](../stories/S-008-audio-analysis.md). Инструменты: `spikes/audio_analysis/analyze.py`, `run.py`, `probe.py positions`. Прогон на 8 дорожках Elated 1, таблица в [CHECKLIST.md](../spikes/audio_analysis/CHECKLIST.md). Примитивы, эталон качества и порядок улучшений: [analysis.md](analysis.md).

### Итог приёмки

**Сетка из файла Logic, звук из экспорта, определение темпа не нужно.** Сравнение корреляцией, выравнивание и подбор громкости работают на реальных дорожках.

**Выбор режима, определение готовности и остаток как критерий не подтвердились.** Цель не точное воспроизведение, а перевод с осознанными потерями, см. принципы в CLAUDE.md. Режимы ниже описывают код спайка. Ручные проверки сняты с приёмки, разделы ниже сохранены как журнал.

### Решение на момент прогона

**Сетка из файла Logic, звук из экспорта, режим анализа выбирается по данным.** Определение темпа не нужно.

- Ноты без аудиорегионов: проверка монофонии и выбор базовой ноты.
- Атак примерно столько же, сколько регионов (допуск 1.2 раза), и нет Loop: каждый регион это один звук. Удары сравниваются корреляцией с порогом 0.97.
- Иначе: окна 1, 2, 4, 8, 16 тактов по сетке. Берётся окно с наименьшим числом разных кусков, при равенстве меньшее. Окна равны, когда равен каждый такт с порогом 0.98.

Обратная сборка показывает, что потеряно при слиянии: она не опирается на эталон и работает на любой дорожке. В режиме windows остаток считается и на каждое срабатывание. Он не доказывает, что потерь нет: порог 0.98 допускает различие, у `LD Saw Harm` остаток окна до −24 дБ.

### Что показала проверка

- Поиска атак мало: разброс старта до 9 мс. Нужны выравнивание, подбор громкости и запас 20 мс перед атакой.
- Обработка канала не мешает: `kick_nerve` на 1 дБ громче исходника и не совпадает с ним, но внутри дорожки все удары одинаковы, остаток −82 дБ.
- Сравнение целого окна теряет варианты: вариант на 7.5 такта сливался в окне 16 тактов. Поэтому сравнение идёт по тактам.
- На протяжных нотах атак может быть меньше, чем регионов: у `LD Saw Harm` 6 атак на 13 позиций. Правило режима двустороннее.
- Высота из MIDI не годится для корня кейгруппы: `Bass Oliver` на всех 7 высотах звучит на 24 полутона ниже нот, ещё до −0.19 полутона. Транспонирование регионов равно 0, причина в файле не прочитана, см. LOGIC-R-007. Корень надо мерить по звуку. Дробное отклонение может быть погрешностью измерения на низких частотах, это не проверялось.
- Порог 0.98 сливает почти равные фразы: начало фраз `LD Saw Harm` отличается от сэмпла до 49 мс и больше, см. [CHECKLIST.md](../spikes/audio_analysis/CHECKLIST.md). Нужно ли их разделять, решается на слух.

### Пороги

Остаток режима events не выше −55 дБ, windows не выше −30 дБ. Порог −20 дБ из плана слишком мягкий: на всех дорожках вышло не выше −32 дБ. Значения сняты с одной песни.

### Что не проверено

- Дорожки с реверберацией между ударами и автоматизацией, где удары перекрываются. В режиме events такого случая в этих 8 дорожках нет. В режиме windows есть: у `LD Saw Harm` предыдущий блок заходит в начало следующего. Громкость подбирается на срабатывание, автоматизация внутри окна не учитывается.
- Правило окон на других песнях. У `shs_roam_breaks` выбраны 8 тактов, потому что это даёт меньше кусков: 2 против 4 при окне 2 такта. Подходит ли это для живой игры, решает пользователь.
- Качество кейгруппы на слух и на Live 2.
- Стеки и полифонические дорожки в анализ не входили.

## Спайк: решение по дорожке

Стори [S-009](../stories/S-009-track-decision.md). Инструменты: `spikes/audio_analysis/decide.py`, `run_decide.py`. Устройство схемы в [analysis.md](analysis.md), результаты в [CHECKLIST.md](../spikes/audio_analysis/CHECKLIST.md).

### Решение

**Дерево сходства и один параметр решительности дают ожидаемое число кусков на 4 дорожках при одном значении 0.775.** Пользователь послушал результат и принял его. Прослушивание нашло щелчки на оборванных краях, это исправлено спадом. Укороченные варианты остаются отдельными файлами. `Fire Glow` сама вступает с середины фразы, поэтому фрагмент начинается так же, это нормально.

### Что показала проверка

- Покадровое сравнение разделило `LD Saw Harm` на основную фразу и варианты 9, 49, 97, совпав с S-008. Порог подобран и под неё: при 0 дБ кусков 5, при +2 дБ кусков 4, такт 17 различается на +1.1 дБ.
- Лимит 4 куска нужен: только он отличает партию с вариациями от партии без повторов.
- Наименьшее число кусков выбирает окно на всю дорожку, наименьшая сумма тактов дробит фразы. Рабочее правило: сумма тактов среди делений в пределах лимита.
- Прореживание всей дорожки вносит различие −50 дБ между точными повторами. Прореживать надо каждый кусок.

### Что не проверено

- Значение и шкала на других песнях.
- Устройство `Fire Glow`: ноты короткие и идут аккордами, фильтр не проверялся.
- Ноты, кейгруппа, стеки в схему не входят.

## Спайк 8. Сборка проекта MPC

Стори [S-005](../stories/S-005-xpj-build.md). Инструмент: `spikes/mpc_build/patch.py`, прошивка 3.10.0.49. Проверка: пользователь открыл все проекты на Live 2.

### Решение

**Проект `.xpj` собирается из шаблона, Live 2 принимает такие файлы.** Правка JSON плюс копирование сэмплов. Проверено на драм-треках, собранных из шаблона, и на кейгруппе, плагине и MIDI-треке, скопированных целиком из другого проекта на Live 2. Своя кейгруппа из сэмплов и пустой плагинный трек не собирались. Выход папкой пока не нужен, но вернуться к вопросу надо, если своя кейгруппа не загрузится.

### Результаты на Live 2

| Кейс | Что собрано | Результат |
|---|---|---|
| `T01 same` | Заново сжатый файл | Открылся |
| `T02 note` | Сдвиг ноты | Верно |
| `T03 notes` | Новые ноты | Верно |
| `T04 pad` | Второй сэмпл на пэде | Верно |
| `T05 track` | Второй драм-трек | Верно |
| `T06 keygroup` | Кейгруппа из другого проекта | Верно. Нота 60 на Live 2 показана как C3 |
| `T07 plugin` | Плагин из другого проекта | Верно, пресет Doom Drone сохранён в состоянии: пользователь выбрал другой, загрузил другой проект, и при перезагрузке `T07` вернулся Doom Drone |
| `T08 midi` | MIDI-трек на устройство | По словам пользователя «всё правильно». Какой порт показан и дошли ли ноты до Minilogue, отдельно не записано |
| `T09 tempo` | Темп 97, две секвенции | Верно |
| `T10 full` | HANDS, драм, кейгруппа, плагин, MIDI | Верно |

### Как собирать

- Шаблон: проект с Live 2. Кейгруппа, плагин и MIDI-трек пока берутся из второго проекта-донора. Правится только JSON, служебные поля `mixer` и `scene` не менялись.
- JSON надо писать тем же форматированием: числа хранятся текстом, как в исходнике, Live 2 пишет float с 17 знаками. Необходимо ли это, не проверялось: так просто безопаснее.
- Трек вставляется перед служебными, запись о нём добавляется в `trackClipMaps` каждой секвенции, список отсортирован по имени.
- Новая нота копируется из существующего события.
- Сэмплы копируются в `<имя>_[ProjectData]`, запись добавляется в `samples` проекта и программы. Имя проекта может отличаться от шаблона, но файл и папка всегда назывались одинаково.
- У пэда копируется заполненный `instruments`, правятся `sampleName`, `sampleFile`, `sliceInfo.End`.

### Что Live 2 меняет при пересохранении

См. [поведение Live 2](formats/mpc/device.md).

### Что не проверено

См. записи `open` в [базе MPC](formats/mpc/INDEX.md). Большие проекты не проверялись.

## Спайк: цвета треков и пэдов Live 2 по эталону Example Colours

Стори [S-025](../stories/S-025-colours-reference.md). Эталон `test-projects/reference/Example Colours.xpj` сохранён Live 2: 64 драм-трека созданы подряд, у первого трека пэды покрашены всеми цветами функции PadColors.

- Цвет трека (`tracks[].colour`, RGB) Live 2 назначает по кругу из 21 значения, первый трек `55FF00`, 22-й снова `55FF00`. Служебные треки красятся фиксированно: Submix `FF6D17`, Return `ECEC24`, Out `A2A9AD`. Реквест MPC-R-014.
- Цвет пэда хранится в `program.programPads.pads.valueN` (N 0–127), 0 значит цвет не задан. Палитра PadColors из 25 цветов: 21 цвет круга треков, три цвета служебных треков и `29B574`. Пэд с сэмплом без заданного цвета Live 2 показывает ярко-зелёным (со слов пользователя; у треков 2–64 `universalPad` 0x00FF00), функция Pad Color сбрасывает цвета пэдов и задаёт их заново. Реквест MPC-R-015.
- Ключи `programPads` соответствуют экрану Pad Color по четырём снимкам пользователя (MPC-R-015): `Type` PAD DISPLAY TYPE (5 это Bright->Velocity), `UnusedPads` EMPTY PADS (1 это dim), `Universal` SINGLE PAD или ALL PADS, `universalPad` цвет режима ALL PADS, `PadsFollowTrackColour` режим Follow Track (цвета пэдов сбрасываются, пэды получают цвет трека, заполненный ярко, пустой приглушён). Выведено по совпадению значений, прямой проверки не было.
- Не установлено: какое поле включает Follow Track (`programPads.PadsFollowTrackColour` или `tracks[].padsFollowTrackColour`), коды имён цветов палитры (`Canary` и другие), принимает ли Live 2 цвета вне палитры.
- Следствие: S-019 (цвета треков) разблокирована, S-020 (палитра вручную) закрыта как ненужная.
