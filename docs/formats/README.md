# База знаний о форматах

Что известно о форматах проектов Logic и MPC. Читают её модели и люди при анализе и разработке. `docs/spikes.md` это журнал проверок и решений, здесь только устройство форматов.

## Что это

Спецификация форматов, снятая разбором файлов из `test-projects/`: от контейнера до поля. Запись описывает структуру, ниже идёт таблица разметки со статусом каждого поля. Неизвестное поле остаётся в таблице со статусом `unknown`. Приложения `schema.tsv`, `records.txt` и `layouts.txt` генерируются `spikes/format_re/`.

## Две независимые базы

`logic/` и `mpc/` не ссылаются друг на друга, общие термины определяются в каждой отдельно. Связь полей Logic и MPC в базы не входит: это логика приложения.

Чтение: сначала `INDEX.md` нужной базы, потом только нужная тема.

## Факт

```markdown
### MPC-041 Короткое название
- status: confirmed
- applies: firmware 3.10, Live 2
- evidence: S-006, кейс K01
- fact: Что известно, одной строкой.
- not: Что не сработало. Необязательное поле.
- superseded-by: MPC-052. Необязательное поле.
- updated: 2026-10-30
```

Каждое поле занимает одну строку. Номера постоянные и не переиспользуются, записи не удаляются.

| Статус | Значение |
|---|---|
| `confirmed` | Проверено на файле с эталоном или на железе |
| `single-sample` | Видели один раз, или эталона нет |
| `hypothesis` | Взято из чужих работ или выведено, не проверялось |
| `refuted` | Опровергнуто, запись остаётся, чтобы не проверять повторно |
| `open` | Вопрос без ответа |

Код продукта опирается только на `confirmed` и `single-sample` без открытых реквестов.

## Реквест

Новое знание или расхождение с базой оформляется реквестом сразу при находке, до продолжения работы. Факты при этом не меняются. Напрямую базу не правит никто, кроме `/kb`.

Файл `<база>/requests/MPC-R-NNN-slug.md` или `LOGIC-R-NNN-slug.md`:

```markdown
---
id: MPC-R-001
status: open
kind: correct
targets: MPC-041
proposed-status: refuted
applies: firmware 3.11
evidence: что показывает находку
found-in: S-008
created: 2026-10-30
---

Что найдено, что предлагается записать, чем отличается от базы.
```

- `status`: `open`, `applied`, `rejected`.
- `kind`: `add` новый факт, `targets` пусто; `correct` правка фактов; `close-open` ответ на запись `open`.
- `found-in`: стори или сессия.

Решение принимает пользователь: `/kb` показывает открытые реквесты, `/kb <номер> accept|reject [комментарий]` применяет или отклоняет. При `accept` факты правятся и в их `evidence` пишется номер реквеста. Файлы реквестов не удаляются.

При расхождении старая запись получает `refuted` или сужает `applies`, новая указывается в `superseded-by`.

## Инструменты

```bash
python3 scripts/formats_check.py
```

```bash
python3 scripts/formats_check.py --export mpc
```

```bash
python3 scripts/formats_check.py --requests
```

Первая команда проверяет базы и стори, Stop-хук запускает её автоматически. Вторая собирает один файл для модели: только `confirmed` и `single-sample`, с `--all` все статусы, факт с открытым реквестом помечен `open-request`. Третья показывает открытые реквесты.
