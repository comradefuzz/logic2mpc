# CLAUDE.md — Logic → MPC Export Planner

## Цель

Приложение для macOS (запуск из терминала, интерфейс в браузере), которое берёт проект Logic Pro и готовит **план экспорта** для Akai MPC Live 2 (прошивка 3.9). Автоматика предлагает черновик, пользователь правит его визуально, затем запускает экспорт. На выходе проект MPC, который проверяется в десктопном приложении и затем переносится на MPC для адаптации под живое выступление.

## Образ результата

1. Пользователь указывает проект Logic.
2. Приложение показывает сводку: сколько драм-треков, кейгрупп и плагинных дорожек предлагается.
3. Группы проекта (папки, например drums, bass) это единица плана. Решение принимается на группе целиком, исключения правятся по отдельным дорожкам.
4. Пользователь объединяет или разделяет группы, прослушивает сэмплы.
5. Экспорт создаёт проект MPC. Первым всегда создаётся пустой трек HANDS.
6. Пользователь проверяет проект в десктопном MPC, затем переносит на Live 2 и адаптирует.

## Три способа экспорта группы

- **Драм-трек:** из каждой дорожки вырезаются сэмплы, раскладываются по пэдам одного драм-трека, ноты секвенции переносятся на пэды. MIDI-дорожки дают готовые ноты, аудиодорожки (лупы, брейки, райзеры) кладутся по позиции на таймлайне.
- **Кейгруппа:** моно-партия (чаще бас) превращается в один базовый сэмпл с питчем, ноты играют его по высотам.
- **Плагин:** пустой MIDI-трек с нотами. Инструмент подбирает пользователь. Автоподбор по тембру в первую версию не входит.

Группа может смешивать способы. Допускается слияние группы в один трек (опционально, например бас для общего сайдчейна).

## Принципы

- **Rules first:** анализ сигнала и правила, LLM опционален и только уточняет спорные случаи (адаптер Advisor: нет / Claude API / локальная модель). Аудио наружу не уходит, только текстовый отчёт.
- **Export Plan это документ:** хранится в файле, версионируется, не зависит от интерфейса. Каждое решение несёт происхождение (rule | llm | user) и confidence.
- **Ничего не выбрасывать:** все партии попадают в проект, их можно слить, но не потерять.
- **Hexagonal Architecture:** чистое ядро (Grid, BarMatrix, Classifier, Strategy, Decision), I/O и LLM за адаптерами. Экспорт отделён от анализа.
- **Fail-safe:** если сборка проекта MPC не получится, выход это папка с программами `.xpm`, WAV и MIDI по секциям.
- **Кэш по хэшам файлов**, возобновление стадий.

## Вне первой версии

- Подбор плагинного инструмента по тембру.
- Раскладка пэдов для ручной игры (вынос на HANDS): делается пользователем на MPC.
- Клонирование остального дефолтного проекта (кроме HANDS).
- Нативная оболочка.

## Спайки (проверять руками до разработки, результаты записывать в docs/spikes.md)

1. **Что читается из проекта Logic:** имена дорожек, папки (Track Stacks), маркеры, темп, размер, регионы. Определяет, берём ли структуру из файла или только из экспорта.
2. **Автоэкспорт из Logic:** можно ли запустить Export All Tracks скриптом, работает ли шаблон имён `NN_Имя`.
3. **MIDI из Logic:** темп, маркеры, раздельные треки; проверить опцию Format 0 для регионов.
4. **Перенос десктоп → стендалон:** версии десктопа и прошивки должны совпадать точно. Проверить MPC Beats и MPC Software: проект с секвенцией, драм-пэдом, MIDI-треком на порт A, плагином, сохранить на SD, открыть на Live 2. Смотреть: грузится ли, звучат ли сэмплы, сохранились ли порт и плагин.
5. **Качество анализа на реальных стемах:** порог сходства при ревербе и автоматизации.
6. **Эталон:** одна песня, собранная вручную в десктопе, как Golden Dataset.
7. **Группа драм-треков → драм-программа MPC:** формат `.xpm`, лимит пэдов (128), перенос нот на пэды.
8. **Формат проекта MPC:** `.xpj` это gzip с JSON; подход clone-and-patch по diff до и после правки. Нужен только если сборка через десктоп не устроит.

## Открытые вопросы

- Сценарий экспорта один на все композиции или свой на песню (с шаблонами)?
- Группа драм-треков всегда в одну драм-программу?
- Открывает ли Live 2 на 3.9 проекты из MPC Beats?

## Рабочий цикл

Единица работы это стори: файл `stories/S-NNN-slug.md`, статус в поле `status`. Доска в `BOARD.md` генерируется и в git не хранится.

Статусы: `analysis` → `plan-review` → `tests` → `dev` → `review` → `acceptance` → `done`, при остановке `blocked`.

- `/story <текст>`: анализ и план, остановка на `plan-review`.
- `/approve NNN`: тесты, разработка, ревью субагентом `reviewer`, остановка на `acceptance`.
- `/accept NNN [что не так]`: приёмка пользователем и один коммит либо возврат в `dev`.
- `/board`: показать доску.

Проверяемая работа всегда получает способ самопроверки: pytest, синтетические стемы или ручной чек-лист. Мелкая правка без нового поведения делается обычной просьбой, без стори. Параллельно: одна стори на сессию в своём worktree.

## Правила кодирования

- Python 3.10+, типизация, чистое ядро без I/O.
- Не писать код вне текущего этапа.
- Не угадывать формат `.logicx` и `.xpj`: только то, что подтверждено спайком.
- Тесты на синтетике: сгенерированные стемы и MIDI с известной структурой повторов.
- Жёсткие правила (тесты до коммита) закреплять хуками, CLAUDE.md только совещательный.

## Стек (предварительно)

Python, numpy/scipy, librosa (анализ), mido (SMF), soundfile (WAV), FastAPI + браузерный интерфейс (волны, перетаскивание, прослушивание).
