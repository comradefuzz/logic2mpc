# CLAUDE.md — Logic → MPC Export Planner

## Цель

Приложение для macOS (запуск из терминала, интерфейс в браузере), которое берёт проект Logic Pro и готовит **план экспорта** для Akai MPC Live 2 (прошивка 3.10). Автоматика предлагает черновик, пользователь правит его визуально, затем запускает экспорт. На выходе материал для MPC, который загружается на Live 2 с SD-карты, проверяется там и адаптируется под живое выступление. Десктопное приложение MPC не используется.

## Образ результата

1. Пользователь указывает проект Logic.
2. Приложение показывает сводку: сколько драм-треков, кейгрупп и плагинных дорожек предлагается.
3. Группы проекта (папки, например drums, bass) это единица плана. Решение принимается на группе целиком, исключения правятся по отдельным дорожкам.
4. Пользователь объединяет или разделяет группы, прослушивает сэмплы.
5. Экспорт создаёт проект MPC. Первым всегда создаётся пустой трек HANDS.
6. Пользователь загружает результат на Live 2 с SD-карты, проверяет и адаптирует.

## Три способа экспорта группы

- **Драм-трек:** из каждой дорожки вырезаются сэмплы, раскладываются по пэдам одного драм-трека, ноты секвенции переносятся на пэды. MIDI-дорожки дают готовые ноты, аудиодорожки (лупы, брейки, райзеры) кладутся по позиции на таймлайне.
- **Кейгруппа:** моно-партия (чаще бас) превращается в один базовый сэмпл с питчем, ноты играют его по высотам.
- **Плагин:** пустой MIDI-трек с нотами. Инструмент подбирает пользователь. Автоподбор по тембру в первую версию не входит.

Группа может смешивать способы. Допускается слияние группы в один трек (опционально, например бас для общего сайдчейна).

## Принципы

- **Rules first:** анализ сигнала и правила, LLM опционален и только уточняет спорные случаи (адаптер Advisor: нет / Claude API / локальная модель). Аудио наружу не уходит, только текстовый отчёт.
- **Export Plan это документ:** хранится в файле, версионируется, не зависит от интерфейса. Каждое решение несёт происхождение (rule | llm | user) и confidence.
- **Перевод, а не копия:** проект переводится из философии Logic в философию MPC. На дорожку выбирается минималистичная стратегия, потери принимаются осознанно и попадают в отчёт. Точность воспроизведения не цель.
- **Партии не теряются:** все партии попадают в проект, их можно слить, но не потерять. Вариации внутри партии можно отбрасывать.
- **Автоматика решает, человек пересматривает:** стратегия всегда сама принимает решение и режет, нарезка это версия. Ревью не зависит от интерфейса: готовые WAV и отчёт. Отказ записывается и даёт новую версию, отброшенное остаётся в плане.
- **Решительность:** один параметр анализа определяет, сколько вариантов оставить, в крайнем правом положении минимум. Уверенность вычисляется на каждое решение отдельно.
- **Hexagonal Architecture:** чистое ядро (Grid, BarMatrix, Classifier, Strategy, Decision), I/O и LLM за адаптерами. Экспорт отделён от анализа.
- **Выход:** один проект MPC (`.xpj`) с сэмплами, собранный из шаблона. Live 2 принимает такие файлы, своя кейгруппа ещё не собиралась, см. спайк 8.
- **Кэш по хэшам файлов**, возобновление стадий.
- **Имена на MPC:** кириллица всегда транслитерируется, имя файла `.xpj` и папки `_[ProjectData]` всегда совпадают.
- **Имена сэмплов:** `КОД_ГРУППА_Имя_NN.wav`. `КОД` это три буквы песни из плана, `ГРУППА` две буквы (`DR`, `BS`, `SY`, `VX`, `FX`, `GT`), `Имя` очищено от паков, темпа, тональности и служебных слов и записано слитно латиницей, `NN` номер внутри имени. Пустое после очистки имя заменяется группой и номером дорожки: `DrTrk24`. Нота пишется в конец только если поле ноты в плане заполнено: `PYR_BS_Bass_01_C2`, сама она не определяется. Автоматика предлагает черновик, в плане имя правится пользователем.

## Вне первой версии

- Подбор плагинного инструмента по тембру.
- Раскладка пэдов для ручной игры (вынос на HANDS): делается пользователем на MPC.
- Клонирование остального дефолтного проекта (кроме HANDS).
- Нативная оболочка.

## Спайки (проверять руками до разработки, результаты записывать в docs/spikes.md)

1. **Что читается из проекта Logic:** имена дорожек, папки (Track Stacks), маркеры, темп, размер, регионы. Определяет, берём ли структуру из файла или только из экспорта.
2. **Автоэкспорт из Logic:** можно ли запустить Export All Tracks скриптом, работает ли шаблон имён `NN_Имя`.
3. **MIDI из Logic:** темп, маркеры, раздельные треки; проверить опцию Format 0 для регионов.
4. **Что Live 2 сохраняет:** формат `.xpj` и `.xpm` на файлах с железа. Загрузка поштучно снята. Плагин проверен в спайке 8, порт A не проверялся.
5. **Качество анализа на реальных стемах:** порог сходства при ревербе и автоматизации.
6. **Эталон:** одна песня, собранная вручную на Live 2, как Golden Dataset.
7. **Драм-программа и кейгруппа:** 128 пэдов и кейгруппа из одного сэмпла работают, см. `docs/spikes.md`.
8. **Сборка проекта MPC:** clone-and-patch из шаблона, Live 2 принимает собранные `.xpj` (подтверждено для скопированных программ).

## База знаний о форматах

`docs/formats/`: две независимые базы, `logic/` и `mpc/`, правила в `docs/formats/README.md`. Читать с `INDEX.md` нужной базы.

- Новое знание о формате или расхождение с базой оформляется реквестом в `requests/` своей базы сразу, до продолжения работы.
- Факты правит только `/kb` по решению пользователя. `/kb` без аргументов показывает открытые реквесты.
- Код продукта опирается только на `confirmed` и `single-sample` без открытых реквестов.
- `docs/spikes.md` это журнал проверок и решений, устройство форматов живёт в базе.

## Анализ аудио

`docs/analysis.md`: раздел «Алгоритм» это эталон анализа с правилами `AN-NNN`, там же примитивы, эталон качества, известные слабости и порядок улучшений.

- Порядок правки: правило, затем тест, затем код. Тест указывает номер правила.
- Правило со статусом `принято` меняется только решением пользователя.
- Расхождение кода с правилом записывается в «Расхождения».

## Рабочий цикл

Единица работы это стори: файл `stories/S-NNN-slug.md`, статус в поле `status`. Доска в `BOARD.md` генерируется и в git не хранится.

Статусы: `analysis` → `plan-review` → `tests` → `dev` → `review` → `acceptance` → `done`, при остановке `blocked`.

- `/story <текст>`: анализ и план, остановка на `plan-review`.
- `/approve NNN`: тесты, разработка, ревью субагентом `reviewer`, остановка на `acceptance`.
- `/accept NNN [что не так]`: приёмка пользователем и один коммит либо возврат в `dev`.
- `/board`: показать доску.
- `/kb [номер accept|reject]`: разбор реквестов к базе знаний.

Проверяемая работа всегда получает способ самопроверки: pytest, синтетические стемы или ручной чек-лист. Мелкая правка без нового поведения делается обычной просьбой, без стори. Параллельно: одна стори на сессию в своём worktree.

## Правила кодирования

- Python 3.10+, типизация, чистое ядро без I/O.
- Не писать код вне текущего этапа.
- Не угадывать формат `.logicx` и `.xpj`: только то, что есть в `docs/formats/`.
- Тесты на синтетике: сгенерированные стемы и MIDI с известной структурой повторов.
- Жёсткие правила (тесты до коммита) закреплять хуками, CLAUDE.md только совещательный.
