## Стори

Длинные сэмплы должны играться в режиме Note On, если все их вхождения звучат целиком до конца своей секции. Если сэмпл хотя бы в одном вхождении длиннее остатка секции, он играется в режиме One Shot и доигрывается до конца. Короткие сэмплы остаются One Shot. Граница «длинного» это параметр экспорта, по умолчанию 2/4 такта.

## Анализ

**Как сейчас.** Режим пэда (`triggerMode`) берётся из описания формата одинаковым для всех пэдов: 0, One Shot ([pad.json](../logic2mpc/spec/pad.json)). Экспортёр ([xpj.py](../logic2mpc/adapters/xpj.py) `add_notes`) ставит ноте длину `min(длина вхождения или образца, остаток секции)`, то есть длинные ноты усекаются по концу секции, число усечённых попадает в потери. При One Shot длина ноты на звук не влияет, поэтому усечение и пауза внутри ноты на слух ничего не меняют, а выключить звук нотой в MPC нельзя.

**Что известно о формате.** `triggerMode` 0 это Sample Play One Shot, 2 Note On: при Note On образец играет, пока нота держится, и обрывается с её концом (MPC-115, кейс P01 на Live 2). Других полей, нужных для Note On, кейсы не выявили.

**Данные Elated (план v15, порог 2/4 такта).** Из 74 экспортируемых образцов 68 длиннее 2/4 такта (1 с при 120 BPM), у 20 из них одно или несколько вхождений звучат за концом секции (`FillJaBouncy`, `LotharBM`, `ArpQuick`, `GatedPad`, `RiseExcellent_01`, `Downlifter*`, `ReversCrash*` и другие). Эти 20 остаются One Shot, остальные 48 длинных получают Note On. Не длиннее порога 6 образцов: четыре ударных (204–304 мс), `FillLong_01` (675 мс) и `FillB_01` (948 мс), они One Shot. Итого 48 Note On и 26 One Shot.

**Принято при анализе, подтвердить при `/approve`.**
- Длинный сэмпл это образец строго длиннее порога `note_on_from`. Порог это параметр экспорта, не поле плана, значение по умолчанию 2/4 такта. Задаётся долей такта (`2/4`, `3/4`, `1/1`), передаётся в `export_project(..., note_on_from=...)`, `app.build` и командой `build --note-on-from 2/4`. Поля порога в интерфейсе в этой стори нет.
- Режим выбирается для пэда целиком по всем его вхождениям: одно вхождение за концом секции делает One Shot весь пэд, потому что `triggerMode` один на пэд.
- Вхождение считается «за концом секции», если его длина (недоигранная длина вхождения или длина образца) больше остатка секции от тика ноты. Вхождения слитых в него фрагментов учитываются (AN-070).
- Нота у Note On пэда имеет длину образца (или недоигранную длину, AN-033). Длина нот у One Shot пэда остаётся усечённой по секции, как сейчас: на звук она не влияет.
- Потери в отчёте: строка «усечена длина ноты» заменяется строкой «звучит за концом секции (One Shot): N образцов, M вхождений». Это перенос AN-063, а не новая потеря.
- Схема плана (вход экспортёра) не меняется: всё нужное уже есть (`ticks`, `occurrences[].length`, секции). Параметр порога добавляется в контракт как опция экспорта вне плана.

3. **Код.** `xpj_spec.pad(..., trigger_mode)`: режим задаётся явно (0 или 2). `xpj.export_project(..., note_on_from=Fraction(2, 4))`: функция `trigger_mode(piece, occurrences, sections, threshold)` по правилу, результат передаётся в `pad`; порог разбирается из строки доли такта, значение не больше 0 отклоняется `ValueError`. `app.build` и `build --note-on-from` пробрасывают параметр. Потери: новая строка вместо усечения длины.
4. **Реестр и контракт.** `fill.py` (текст решения для `triggerMode`), `export.tsv`, `docs/contracts/xpj-export.md` (режим пэда выбирается экспортёром, схема не меняется).
5. **Данные.** Пересобрать Elated, проверить 74 образца: 48 Note On, 26 One Shot, ноты и пэды без изменений.

Затрагиваются: `docs/analysis.md`, `logic2mpc/adapters/xpj_spec.py`, `logic2mpc/adapters/xpj.py`, `logic2mpc/app.py`, `logic2mpc/__main__.py`, `spikes/mpc_spec/fill.py`, `docs/formats/mpc/export.tsv`, `docs/contracts/xpj-export.md`, `tests/test_xpj_spec.py`.
