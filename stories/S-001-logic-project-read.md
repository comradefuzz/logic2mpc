## Стори

Спайк: выяснить, что читается из проекта Logic

## Анализ

Это спайк 1 из CLAUDE.md. Он должен ответить, берём ли структуру проекта (дорожки, папки, маркеры, темп, размер, регионы) из файла `.logicx` или только из экспорта. От ответа зависит вход всего конвейера и открытый вопрос «Читается ли папочная структура из файла Logic?». `docs/spikes.md` пока не существует, предыдущих результатов нет.

### Что уже видно (только чтение, Logic Pro 10.8.1)

Осмотрены `Fuzz - Pyro.logicx` (1,5 ГБ, 135 дорожек) и демо `MONTERO.logicx`. Это наблюдения по двум проектам, а не подтверждённый формат.

- `.logicx` это папка-пакет: `Resources/ProjectInformation.plist`, `Media/`, `Alternatives/NNN/`.
- В каждой альтернативе есть `MetaData.plist`, `DisplayState.plist`, `DisplayStateArchive`, `ProjectData`, `WindowImage.jpg`, `Project File Backups/`, `Undo Data.nosync/`.
- Номера альтернатив бывают не с нуля: у Pyro это `000`, у MONTERO `002`.
- `MetaData.plist` читается штатно (`plistlib`). В нём есть `BeatsPerMinute`, `SongSignatureNumerator`, `SongSignatureDenominator`, `SongKey`, `SongGenderKey`, `SampleRate`, `NumberOfTracks`, `AudioFiles`, `UnusedAudioFiles`, `SamplerInstrumentsFiles`.
- `MetaData.plist` даёт одно значение темпа и размера, смены по ходу песни там не видны. Есть ли в нём темп начала или основной, неизвестно.
- `ProjectData` это бинарный файл без документации (14 МБ у Pyro). Сигнатура `23 47 C0 AB`, в начале видна метка `gnoS`. В файле находятся текстовые строки, включая похожие на имена дорожек, но их принадлежность не проверена.

### Что неясно

- Как в `ProjectData` устроены дорожки, Track Stacks и их вложенность, маркеры, карта темпа, смены размера, регионы и их позиции.
- Какая альтернатива активна и где это записано.
- Насколько структура устойчива между проектами и версиями Logic. Файл недокументирован, разбор может сломаться после обновления Logic, поэтому устойчивость входит в вывод спайка наравне с самим чтением.
- Есть ли готовые открытые разборщики `ProjectData`, и насколько им можно верить.
- Что дают запасные пути: Export All Tracks, MIDI, а также экспорт в AAF и Final Cut Pro XML. Наличие этих экспортов в Logic и их содержимое на проекте не проверялись.

### Вопросы

Блокирующих вопросов нет. Решения, принятые по умолчанию, вынесены в план: контрольный проект делает пользователь, скрипт разведки остаётся в репозитории как материал спайка.

## План

Правило спайка: исходные `.logicx` никогда не меняем. Тестовые проекты лежат в `test-projects/` в корне репозитория, папка в `.gitignore`. Туда же идёт контрольный проект, а копии реальных проектов берутся только с `Alternatives/` и `Resources/`, без `Media/`. В этой стори не появляется код продукта и не принимается формат как «подтверждённый» без сверки с контрольным проектом.

1. **Контрольный проект (делает пользователь).** Новый проект `test-projects/Spike Control.logicx` с заранее известной структурой:
   - Два Track Stack с именами `CTRL_drums` (summing) и `CTRL_bass` (folder), внутри первого вложенный стек.
   - Минимум по одной аудио- и MIDI-дорожке в стеках и одна вне их, дорожки с уникальными именами `CTRL_…`.
   - Регионы с уникальными именами на известных тактах.
   - Три маркера с уникальными именами на известных тактах.
   - Смена темпа и смена размера на известных тактах.
   - Вторая альтернатива с отличием в имени одной дорожки, она остаётся активной.
   - Заполненная таблица ожидаемых значений (эталон для сверки) записывается в `docs/spikes.md`. Шаблон таблицы и подробный чек-лист готовлю я.
2. **Поиск существующих решений.** Открытые разборщики и описания `ProjectData`. Найденное считается гипотезой до сверки с контрольным проектом.
3. **Разведка `ProjectData`.** Скрипт `spikes/logic_read/probe.py`, только чтение: разбор плистов, разбиение бинарного файла на блоки, поиск имён `CTRL_…`, сравнение версий.
   - Основной приём это дифф: сохранить контрольный проект, сделать одну правку (сдвиг региона, смена темпа, перенос дорожки в стек), сохранить копию и сравнить. Так поле находится по изменению, а не догадкой.
   - Правки по списку из скрипта делает пользователь, либо они берутся из `Project File Backups/`, если там видны нужные изменения.
4. **Сверка на реальных проектах.** Найденные правила прогоняются на контрольном проекте, Pyro и ещё одном проекте другого года (например Elated или Satori), плюс MONTERO для другой альтернативы. Итог сверяется с тем, что показывает Logic на экране.
5. **Запасные пути.** На контрольном проекте вручную проверить, какие поля из таблицы дают экспорт MIDI, AAF и Final Cut Pro XML. Глубина ровно такая, чтобы заполнить колонку «другой источник». Шаблон имён и автозапуск экспорта относятся к спайкам 2 и 3 и здесь не проверяются.
6. **Вывод.** Создать `docs/spikes.md` с разделом спайка 1:
   - Таблица: поле (дорожки, папки, вложенность, маркеры, темп, карта темпа, размер, регионы и позиции, альтернатива) × источник × статус (подтверждено, частично, не читается) × на каких проектах проверено.
   - Рекомендация: структура из файла, из экспорта или смешанно, с оценкой риска поломки при обновлении Logic.
   - Обновить открытый вопрос про папочную структуру в CLAUDE.md.

**Файлы:** `docs/spikes.md`, `spikes/logic_read/probe.py`, `CLAUDE.md` (только открытый вопрос), `.gitignore` (`test-projects/`).

**Не входит:** адаптер чтения Logic для продукта, модель данных Export Plan, запись в `.logicx`, автоэкспорт, анализ аудио.
