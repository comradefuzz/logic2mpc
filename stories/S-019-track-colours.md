## Стори

Треки собранного проекта MPC получают разные цвета, по цвету треки группы отличаются от соседей. Сейчас после экспорта все треки голубые.

## Анализ

**Как сейчас.** [xpj_spec.py](../logic2mpc/adapters/xpj_spec.py) `drum_track` берёт `colour` из `logic2mpc/spec/track.json`: 8959 (0x0022FF, голубой), это значение `Drum 001` из `Empty.xpj`. Его получают все треки. Раньше, при копировании донора, было то же самое.

**Что известно о формате.**
- `tracks[].colour`: целое число, RGB (0xRRGGBB), MPC-033/project.md, статус `hypothesis`. В 33 образцах 15 значений.
- Без поля `colour` трек голубой (T02, MPC-114), так что голубой это умолчание Live 2.
- Среди образцов, сохранённых на Live 2, пользовательские треки имеют значения: 0x0022FF, 0x00AAFF, 0x00FF80, 0x00FFC4, 0x11FF00, 0x5200FF, 0x6F00FF, 0xB200FF, 0xE6FF00, 0xFF0000, 0xFF00BB, 0xFF4400, 0xFF8800 (13 цветов, в основном проект Rataklang, цвета выбраны вручную). Остальные три значения (0xA2A9AD, 0xECEC24, 0xFF6D17) принадлежат служебным трекам Out, Return, Submix.
- Показывает ли Live 2 произвольное значение RGB без привязки к палитре, на железе не проверялось. Поэтому используются только наблюдавшиеся значения.
- `padsFollowTrackColour` везде false: пэды цвет трека не наследуют, их цвета в стори не трогаются.

**Что не известно.** Полная палитра цветов треков Live 2 и её порядок: её снимает с железа [S-020](S-020-track-colour-palette.md). Стори блокирована до приёмки S-020.

**Принято при анализе, подтвердить при `/approve` после приёмки S-020.**
- Цвета задаются экспортёром по порядку групп плана, без полей в плане: выбор цвета пользователем это отдельная стори.
- Палитра это цвета из результата S-020, взятые в порядке, где соседние отличаются сильнее всего. После [S-021](S-021-no-hands-track.md) трека HANDS нет: первая группа получает первый цвет палитры.
- Группы получают цвета по кругу из палитры. Когда групп больше, чем цветов, цвета повторяются, это попадает в отчёт потерь.
- Значения палитры берутся из S-020 без догадок по образцам.
- Цвет не зависит от способа экспорта и кода группы (DR, BS и других).
- Клипы и пэды цвет не меняют: в клипе `colour` 0 по умолчанию, пэды цвет трека не наследуют.

## План

1. **Палитра.** В [xpj_spec.py](../logic2mpc/adapters/xpj_spec.py) константа `PALETTE` из значений S-020 и `drum_track(name, armed, colour)`: `colour` задаётся явно. Значения палитры в `docs/formats/mpc/export.tsv` помечаются как решение (`fill.py`).
2. **Сборка.** В `export_project` группа с номером n (с 1) получает `PALETTE[(n - 1) % len(PALETTE)]`. Когда групп больше, чем цветов, в `losses` добавляется строка о повторе цветов.
3. **Контракт.** В `docs/contracts/xpj-export.md` одна строка: цвет трека задаётся порядком групп, вход схемы не меняется.
4. **Документы.** Если ручная проверка покажет, что Live 2 принимает значения вне палитры или палитра шире, реквест к базе по результату.

Затрагиваются: `logic2mpc/adapters/xpj_spec.py`, `logic2mpc/adapters/xpj.py`, `spikes/mpc_spec/fill.py` (текст решения), `docs/formats/mpc/export.tsv`, `docs/contracts/xpj-export.md`, `tests/test_xpj_spec.py`.

Не входит: выбор цвета пользователем и поле цвета в плане, цвет по способу экспорта или коду группы, цвета пэдов и клипов, произвольные RGB вне наблюдавшихся, цвета служебных треков.

## Реквесты

Нет. Новое знание о палитре (если ручная проверка его даст) оформляется реквестом при приёмке.

## Тесты

### Автотесты

- [ ] Группы, пока их не больше цветов палитры, получают разные цвета, все из `PALETTE`, ни одна не голубая
- [ ] Группа сверх числа цветов повторяет цвет первой, в `losses` есть строка про повтор цветов; при числе групп не больше цветов такой строки нет
- [ ] Цвета не зависят от содержимого групп: тот же порядок групп даёт те же цвета, сборка остаётся детерминированной (байты совпадают)
- [ ] Ни одно значение `colour` вне `PALETTE` и `track.json` не пишется; существующие тесты экспорта проходят

### Ручные проверки

- [ ] Собрать Elated новым экспортом и открыть на Live 2: все треки разных цветов, звук и ноты как раньше
