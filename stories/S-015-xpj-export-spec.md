## Стори

Уточнить формат XPJ так, чтобы получить полноценное описание для экспорта, и подготовить набор проектов с чек-листом проверок на MPC. Служебные треки Out, Submix, Return могут не требоваться в описании: если так, экспорт их не касается совсем, а при использовании шаблона их гарантированно создаёт сам MPC.

## Анализ

**Цель.** Получить описание `.xpj` в таком виде, чтобы экспорт собирал всё, что создаёт сам, из описания, без копирования объектов из чужого проекта (S-014), и знал, чего не касается. Результат это три вещи: реестр полей для экспорта, набор проектов-кейсов и чек-лист для Live 2.

**Что уже есть.** База `docs/formats/mpc/` (33 файла, 3122 путей в `schema.tsv`, прошивка 3.10.0.49), спайки 4–8: `.xpj` собирается правкой JSON, драм-программа до 128 пэдов, MIDI-трек без инструмента (MPC-072), вставка трека (MPC-023), длина секвенции (MPC-035, не открывалась на железе). Структура в базе описана, но не отвечает на два вопроса, нужных экспорту: **какие поля обязательны** и **какое значение ставить**, когда в образцах их несколько.

**Служебные треки Out, Submix, Return.** Установлено (MPC-110, `single-sample`): пустой проект Live 2 содержит 29 треков, `Drum 001` и 28 служебных, и удалить служебные на Live 2 нельзя. Следствие: любой проект, сохранённый Live 2, их содержит, поэтому экспорт поверх шаблона получает их гарантированно, а в описание экспорта они не входят и задачу не касаются. Корень проекта при сборке с нуля сводится к десяти ключам, остальное можно не писать (MPC-113), экспорт поверх шаблона его не правит. Кейсы `Z01`–`Z03` отвечали на другой вопрос: открывается ли проект, собранный с нуля без служебных треков. Результат (MPC-112): открываются все три, звук есть, но Live 2 не пересоздаёт отсутствующие треки, и без Submix и Return в MIX их не добавить. Значит служебные треки для открытия не обязательны, но сборка с нуля даёт проект беднее шаблона. Вопрос нужен только сборке без шаблона, которую в продукте заменяет шаблон пользователя ([S-014](S-014-project-template.md), COULD). Не проверено: нужны ли правки записей служебных треков в `trackClipMaps`, когда экспорт поверх шаблона добавляет секвенции. Это проверяет [S-014](S-014-project-template.md).

**Метод.** Не гадать, а сокращать проект блоками: чем проще проект, где ещё открывается на Live 2, тем меньше обязательное. Кейсы собираются правкой реальных проектов из `test-projects/mpc` (мутация, не сборка для продукта). Раунд 1 проверяет блоки целиком (корень, служебные треки, поля трека, пэда, клипа). Раунд 2 понадобился, потому что в раунде 1 пэд (`P04`) и событие-нота (`Q02`) сломались без постоянных полей: он делит эти блоки на группы и находит обязательное поле. Поля с несколькими значениями в образцах кейсами не проверялись: их значения взяты из `Empty.xpj`, из плана или решены (см. Итог спайка).

**В объёме.** Объекты, которые создаёт экспорт: драм-трек с драм-программой, пэд и слой, запись сэмпла, клип, событие-нота, секвенция, MIDI-трек (способ «плагин»), общие поля проекта, которые экспорт пишет (темп, размер).

**Вне объёма.** Кейгруппа (на холде), плагинный и аудиотреки, смена темпа и размера внутри песни (MPC-029, MPC-030), Song Mode (MPC-031, нужен образец с железа, сохранённый `Sample Song` из спайка 7), порт A (MPC-044).

### Вопросы

- [x] Служебные треки: в интерфейсе MPC видны и отличаются от обычных, удалить их нельзя (MPC-110). Следствие: любой проект, сохранённый Live 2, их содержит, для экспорта поверх шаблона они гарантированы и в описание не входят. Кейсы `Z` нужны только для сборки с нуля
- [x] Настройки, которые экспорт задаёт явно: режим воспроизведения, полифония, цвет. Громкость и панорама учтены в исходном аудио, в обычном сценарии не передаются, но передавать их в отдельных сценариях можно: поля заносятся в реестр как необязательные и без кейсов
- [x] Образец минимального проекта: `test-projects/reference/Empty.xpj`

### Что дал образец Empty.xpj

Сохранён Live 2, 3.10.0.49. 29 треков: `Drum 001` (тип 0, `recordArm` true) и 28 служебных. Секвенций нет (`sequences` пуст), сэмплов нет, `currentTrackIndex` 0. Значит минимальный проект Live 2 не содержит ни одной секвенции (MPC-110): описание секвенции и клипов надо задавать с нуля, а шаблон «Empty» не должен требовать секвенции (замечание в S-014).

`recordArm` установлен (MPC-111, `confirmed`): true значит, что игра на пэдах идёт в этот трек, несколько таких треков слышат пэды одновременно, на воспроизведение секвенции поле не влияет. Live 2 при сохранении оставляет true только у `currentTrackIndex` (MPC-104). Поэтому описание трека задаёт `recordArm` явно, а не наследует из образца. Кейс `T04` проверяет только, открывается ли проект с выключенным полем у всех треков. Поле цвета есть только у трека (`colour`), у пэда отдельного поля в образцах нет, `padsFollowTrackColour` везде false.

Поля пэда, которыми экспорт может управлять (по `schema.tsv`): `triggerMode` {0, 2}, `polyphony` {0, 1, 4}, `monophonic`, `whichMuteGroup` {0, 1, 2}, `zonePlayTime` {0, 1, 2}, `warpEnable`, `bpmLock`, `loopLock`, `stretchPercentage`. Смысл значений установлен кейсами `P01`–`P06` (MPC-115).

## Итог спайка

- Корень проекта: десять ключей, остальное необязательно (MPC-113).
- Служебные треки не обязательны для открытия, но Live 2 не пересоздаёт отсутствующие (MPC-112).
- Трек, программа, слой, клип, запись сэмпла, секвенция, MIDI-трек работают без постоянных полей (MPC-114, MPC-116, MPC-117).
- Обязательны только `instruments[].version` (MPC-117) и `events[].version` (MPC-118).
- Пэд: `triggerMode` 0 One Shot, 2 Note On, полифония, варп, Mute Group работают как задумано (MPC-115).
- `recordArm` задаётся явно, true только у текущего трека (MPC-111).
- Реестр `export.tsv`: 194 поля `no`, 2 поля `yes`, остальные `unknown` (не проверялись, значение для экспорта взято из `Empty.xpj`, плана или решения). Четыре поля вне Empty решены без проверки: `rootNote` 60, `loadImpl` 0, `autoSelectTrackIndex` −1, `channel` 0.

## План

1. **Реестр полей.** `spikes/mpc_spec/registry.py` по `schema.tsv` для объектов «В объёме» делит поля на постоянные (одно значение), переменные (несколько) и ссылочные (имя, путь, индекс). Выход: `docs/formats/mpc/export.tsv`: путь, класс, наблюдавшиеся значения, обязательность (`unknown`), значение для экспорта (пусто), факт (пусто). Громкость и панорама помечаются как необязательные.
2. **Кейсы раунда 1.** `spikes/mpc_spec/cases.py` пишет в `test-projects/mpc/spike9/` проекты, каждый одним изменением исходного. Основы: `reference/Empty.xpj` (корень, служебные, трек), `spike7/D01 pads16` (пэды, клипы, ноты), `spike7/M01 midi` (MIDI-трек). Папка данных копируется под новое имя. Кейсы:
   - `Z01` без служебных треков, `Z02` без Out, `Z03` без Submix и Return.
   - `R01` без `mixer`, `R02` без `scene`, `R03` без `songs`, `R04` без `assignable*`, `qlink*`, `rowLaunch*`, `midiLearnSettings`, `parameterSnapshotterData`, `R05` без `gui*`, `tui*` и клип-матриц, `R06` минимальный корень, все ключи кроме белого списка удалены.
   - `T01` трек без постоянных полей по реестру, `T02` без `colour`, `T03` без `program.mixable`, `T04` `recordArm` выключен у всех.
   - `P01` `triggerMode` меняется на другое наблюдавшееся значение (0 на 2 и обратно) на заполненных пэдах, `P02` `monophonic` выключен при `polyphony` 1 (в исходном D01 пэды монофонические, `triggerMode` 0, группа 0), `P03` `monophonic` выключен и `polyphony` 4, `P04` пэды без постоянных полей по реестру, `P05` `warpEnable` true, `P06` `whichMuteGroup` 1 на двух пэдах.
   - `Q01` клип без постоянных полей, `Q02` событие без постоянных полей, `Q03` запись сэмпла без постоянных полей, `Q04` секвенция без постоянных полей.
   - `M01` MIDI-трек без постоянных полей.
   Итого 24. `--checklist` создаёт `CHECKLIST.md` из того же списка, чтобы они не расходились.
3. **Раунд 2** (`spikes/mpc_spec/cases2.py`, проекты в `test-projects/mpc/spike9b/`, чек-лист `CHECKLIST2.md`, 12 кейсов): внутри блоков, где раунд 1 показал обязательные поля. Основа `spike7/D01 pads16`, каждый кейс убирает одну группу полей. Пэд: `B01` только `version`, `B02` `coarseTune`, `fineTune`, `velocityScale`, `B03` `layerCrossfade*` и `midiOut*`, `B04` флаги, `B05` всё, кроме `version`. Слой: `B06` `version`, `B07` остальное. Событие: `E01` `version`, `E02` `selected`, `E03` `version` ноты, `E04` модификаторы, `E05` `probability`, `ratchet`, `articulation`.
4. **Итоговое описание.** `spikes/mpc_spec/fill.py` заполняет `export.tsv` по результатам раундов и Раздел «Спайк 9» в `docs/spikes.md`, реквесты MPC-R-004..R-011 приняты в факты MPC-110..MPC-118. Факты правит только `/kb`.
5. **Проверка реестра.** `scripts/formats_check.py`: каждый путь из `export.tsv` есть в `schema.tsv`, ссылка на факт существует и имеет статус `confirmed` или `single-sample`.

Затрагиваются: `spikes/mpc_spec/` (`registry.py`, `cases.py`, `cases2.py`, `fill.py`, `CHECKLIST.md`, `CHECKLIST2.md`, тесты), `docs/formats/mpc/export.tsv`, `docs/formats/mpc/INDEX.md`, `scripts/formats_check.py`, `scripts/test_formats_check.py`, `docs/spikes.md`, `CLAUDE.md` (список спайков).

Не входит: код продукта, кейгруппа, плагин, аудиотреки, смена темпа и размера, Song Mode, порт A, другие версии прошивки, кейсы на громкость и панораму.

## Итог ревью

Субагент `reviewer`, один раунд, до раунда 2: `cases2.py`, `fill.py` и результаты раундов он не видел. Тесты зелёные (46 в `spikes/mpc_spec` и `scripts`, полный прогон 378 прошли, 15 пропущено), `formats_check.py` без ошибок. Реестр совпадает с генератором, все 24 кейса меняют только заявленное, чек-лист строится из того же списка, формат сверх базы не угадывается.

Одно расхождение: в `spike9/` остался проект `P02 mono` от прежнего имени кейса, и вся папка уехала бы на Live 2 без строки в таблице. Исправлено: `cases.py` удаляет проекты прежних запусков (`remove_stale`), тест добавлен, в папке 24 проекта.

Замечание по ходу работы: в исходном `D01 pads16` пэды уже монофонические (`monophonic` true, `polyphony` 1, `triggerMode` 0), поэтому кейс «монофония» был бы копией исходного. Он заменён на `P02 mono-off`, тесты соответствуют.

Вне этой стори в рабочем дереве лежат правка `recordArm` и фильтр `._*` из прошлых просьб (`xpj.py`, `tests/test_export.py`, `tests/test_overview.py`, MPC-R-003) и стори S-014. В коммит S-015 их включать не нужно.
