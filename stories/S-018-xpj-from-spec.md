## Стори

Экспорт собирает проект MPC по описанию формата (`docs/formats/mpc/export.tsv` и факты базы), а не копирует объекты из донорского проекта. Донорского проекта в пакете нет.

## Анализ

**Как сейчас.** [xpj.py](../logic2mpc/adapters/xpj.py): `write_project` читает встроенный `logic2mpc/template/template.xpj` (копия `Spike4 A.xpj`) и копирует из него всё: корень проекта, служебные треки, трек `Drum 001` (он же основа HANDS и каждой группы), запись сэмпла, ноту, клип, секвенцию. Зависимости от донора: `TEMPLATE`, `BASE_TRACK`, `note_template`, `clear_pads`, `rename_first_track`, `entry_base`, `filled`, `insert_track` (клип из `clips[0]`), `make_sequences` (копия `sequences[0]`). Скрытое состояние копируется вместе с объектами (случай `recordArm`, MPC-111).

**Что дал спайк S-015.**
- Корень проекта при сборке с нуля сводится к десяти ключам (MPC-113): `version`, `key`, `masterTempoEnabled`, `masterTempo`, `samples`, `tracks`, `sequences`, `currentTrackIndex`, `currentSequence`, `engineMode`.
- Служебные треки Out, Submix, Return для открытия не обязательны (MPC-112), но Live 2 их не пересоздаёт: проект без Submix и Return беднее обычного, в MIX их не добавить.
- Обязательны только `instruments[].version` (MPC-117) и `events[].version` (MPC-118), остальные постоянные поля проверенных блоков не нужны (MPC-114, MPC-116).
- `recordArm` true только у текущего трека (MPC-111); поведение пэда: `triggerMode` 0 One Shot, 2 Note On, полифония, варп, Mute Group (MPC-115).
- Реестр `export.tsv`: для каждого поля `required` (yes, no, unknown), значение для экспорта (из `Empty.xpj`, из плана или решение), факт. 194 поля `no`, 2 `yes`, 713 `unknown` (не проверено на железе).

**Что остаётся неизвестным.** 713 полей `unknown`: убирать их не проверялось. Решение: писать их все со значением из `export.tsv` (то, что пишет Live 2 в `Empty.xpj`), а `no` не писать. Так результат ближе всего к проекту, который сохраняет сам Live 2. Правки записей служебных треков в `trackClipMaps` при сборке с нуля не требуются (служебных треков нет).

**Решения, принятые при анализе (подтвердить при `/approve`).**
- Проект собирается с нуля без служебных треков. Потеря (нет Submix и Return, MPC-112) попадает в отчёт экспорта. Сборка поверх пользовательского шаблона остаётся в [S-014](S-014-project-template.md), COULD.
- Принудительный трек HANDS остаётся как есть: теперь он собирается из описания, а не копией. Его удаление в S-014.
- Описание формата живёт в коде: модуль `logic2mpc/adapters/xpj_spec.py` с функциями `root`, `drum_track`, `drum_pad`, `layer`, `sample_entry`, `clip`, `note_event`, `sequence`. Значения ставятся по `export.tsv`, у каждой константы ссылка на факт.
- Значения четырёх полей без проверки (`rootNote` 60, `loadImpl` 0, `autoSelectTrackIndex` −1, `channel` 0) берутся из `export.tsv` как есть.
- Донор `logic2mpc/template/` удаляется из пакета.

**Контракт экспортера.** Код экспорта планируется вынести в отдельный проект, поэтому его границы фиксируются документом, а не остаются неявными в коде. Сейчас [xpj.py](../logic2mpc/adapters/xpj.py) тянет из ядра `core.plan` (Plan, Group, PlanPiece, Occurrence, `is_exported`, `occurrences_of`), `core.sections` (Section, `place`), `core.model` (`BAR`), `core.names` (`transliterate`) и `core.overview` (`summarize` для чтения готового проекта). Вызывается из `app.build` после подтверждения плана; сборка и перезапись папки вывода живут в `app.py`.

Что фиксирует контракт (JSON Schema входа `logic2mpc/spec/export-plan.schema.json` (схема едет вместе с экспортёром) и короткий документ `docs/contracts/xpj-export.md` про выход, отказы, отчёт и границы):
- **Вход.** Export Plan версии `PLAN_VERSION` и папка сэмплов. Вход описан JSON Schema: только поля, которые экспортёр читает, остальные схема разрешает, но экспортёр их игнорирует. Экспортёр проверяет план по схеме до записи. План: `bpm`, `sections[]` (`name`, `start`, `bars`), `groups[]` (`name`, `tracks[].pieces[]`: `name`, `file`, `ticks`, `lead`, `export`, `merged_into`, `occurrences[]` с `tick`, `gain`, `length`). Остальное (confidence, origin, правила анализа) экспортёр не читает и не должен читать. Единицы: тики `PPQ` 960, `BAR` 3840, кадры сэмплов.
- **Выход.** `<имя>.xpj` и папка `<имя>_[ProjectData]` с одним именем, в папке WAV сэмплов. Имя: транслитерация, правило с кириллицей. Возвращаемое значение: путь к `.xpj`.
- **Отказы.** Проверки до записи: больше 128 фрагментов в группе, нет WAV (`ValueError`, `FileNotFoundError`). После отказа ничего не записано.
- **Отчёт.** Потери сборки (нет служебных треков, длинные ноты усечены по секции, фрагменты слиты) отдаются экспортёром структурой, а не печатью.
- **Формат.** Что пишется, определяют `export.tsv` и факты базы `docs/formats/mpc/` (прошивка 3.10.0.49). Описание поставляется вместе с экспортёром, без него экспортёр не собирается.
- **Границы.** Экспортёр не зависит от анализа сигнала, интерфейса, кэша и Logic. Зависит только от тонкой модели плана и транслитерации. Чтение готового проекта (`read_overview`) в контракт экспортёра не входит.
- **Версионирование.** Версия контракта растёт при изменении входа, выхода или описания формата; план другой версии отклоняется явной ошибкой.

**Решения по контракту (подтвердить при `/approve`).**
- Контракт входа это JSON Schema, исполняемая граница, а не проза: экспортёр валидирует план по схеме на входе, вынесенный проект получает схему как есть. Документ про выход и границы остаётся коротким, тест сверяет его список импортов с кодом. Кодогенерация моделей не нужна.
- Для выноса экспортёру нужна своя тонкая модель плана (`ExportPlan`) вместо импорта `core.plan`. В этой стори вводится только проверка границы: экспортёр импортирует из ядра ограниченный список имён, тест следит за ним. Сам перенос в отдельный проект не входит.
- Отчёт потерь возвращается из `write_project` (дополнение к пути), вызывающий код решает, что показать.

## План

1. **Описание в коде.** `logic2mpc/adapters/xpj_spec.py` и файлы `logic2mpc/spec/*.json`, которые порождает `scripts/build_spec.py` из `export.tsv` и эталонов (`Empty.xpj`, `D01 pads16`): функции возвращают объект целиком (все поля, кроме `no`). Размер пустого драм-трека 128 пэдов собирается циклом, у пэда и события `version` обязательно. Числа с точностью хранятся как `Number`.
2. **Сборка.** `write_project` строит корень, треки HANDS и групп, записи сэмплов, секвенции по секциям, клипы и события из описания, без чтения донора. `recordArm` true только у текущего трека, у остальных false. Темп плана в `masterTempo` и секвенции. Удаляются `TEMPLATE`, `BASE_TRACK`, `note_template`, `clear_pads`, `rename_first_track`, `logic2mpc/template/`.
3. **Отчёт.** В отчёт экспорта пишется потеря: проект собран без служебных треков Out, Submix, Return.
4. **Проверка по эталону.** Тест сравнивает объекты описания с `Empty.xpj` (драм-трек `Drum 001` без полей `no`) и с `D01 pads16` (пэд, слой, событие): ключи и значения совпадают с учётом реестра.
5. **Железо.** Один проект Elated, собранный новым экспортом, открывается на Live 2: треки, пэды, ноты, звук.
6. **Контракт.** `logic2mpc/spec/export-plan.schema.json`: JSON Schema входа (поля плана, единицы в описаниях, версия контракта как константа). `docs/contracts/xpj-export.md`: выход (имена, папка), отказы, отчёт потерь, зависимость от описания формата, границы. `write_project` проверяет план по схеме до записи, возвращает путь и отчёт потерь. Тест следит за границей: список имён, которые `xpj.py` и `xpj_spec.py` импортируют из ядра, равен списку в документе. Библиотека `jsonschema` добавляется в `requirements.txt`.
7. **Документы.** CLAUDE.md: строка «Выход» (сборка по описанию), «Вне первой версии» (шаблон пользователя в S-014); `docs/spikes.md` без новых спайков.

Затрагиваются: [xpj.py](../logic2mpc/adapters/xpj.py), новый `xpj_spec.py`, новые `logic2mpc/spec/` (описание и схема), `mpcfile.py`, `xpj_view.py`, `scripts/build_spec.py`, `docs/contracts/xpj-export.md`, `requirements.txt`, `tests/test_export.py`, `tests/test_overview.py`, `app.py` (отчёт), CLAUDE.md.

Не входит: сам вынос экспортёра в отдельный проект, шаблон пользователя и вставка в него (S-014), служебные треки, кейгруппа, плагин, аудиотреки, смена темпа и размера внутри песни, Song Mode, проверка 713 полей `unknown` на железе.

## Итог ревью

Субагент `reviewer`, один раунд. Тесты зелёные, ключевые проверки в порядке: донора нет, корень из десяти ключей, `version` у пэдов и событий, схема читает ровно используемые поля, детерминизм, ошибки до записи.

Подтверждённые расхождения, исправлены:
- Экспортёр писал три поля с `required = no` (`loopEndBar`, `loopEndPulses` секвенции и `loopEndPulses` клипа). Это длина цикла, равная длине секции, а не необязательная константа: в реестре они переведены в `unknown` со значением «из плана» (без ссылки на факт, MPC-035 остаётся гипотезой). Добавлен общий тест: ни один путь `no` из реестра не записывается нигде в проекте.
- Не писался `program.samples[].version` (реестр `unknown`, пишем). Для записи сэмпла в программе трека добавлен отдельный объект `program_sample.json`, в пуле проекта `version` по-прежнему нет.
- `metadata.key` «C Major» в реестре значилось «из плана», хотя в плане тональности нет: в реестре помечено решением.
- Совпадающие имена треков после транслитерации (в том числе HANDS) теперь дают `ValueError` до записи; в контракте сказано, что имена фрагментов экспортёр не транслитерирует и они должны быть латиницей.

Вне плана, оставлено: сообщение 404 «нет такого фрагмента» в `web.py` изменено заменой слова «кусок» в этой же сессии, не частью S-018. Изменения `docs/formats/mpc/` и реквесты относятся к S-015.

## Заметки разработки

- Тесты `tests/test_session.py` подменяли `app.build` и `xpj.write_project`. Сборка теперь идёт через `app.build_result` и `xpj.export_project` (нужен отчёт потерь), поэтому в двух тестах изменена только цель подмены, содержание проверок то же.
- `read_overview` вынесен в `xpj_view.py`: он тянет `core.overview`, а экспортёр от него не зависит. Тесты просмотра вызывают `xpj_view.read_overview`.
- Схема входа лежит в `logic2mpc/spec/`, а не в `docs/contracts/`: она нужна экспортёру в рантайме и едет вместе с ним.
- Поля `required = no` из реестра не пишутся все вместе. Раунды спайка проверяли их по группам и блокам, но не одним проектом целиком, поэтому ручная проверка на Live 2 это первая проверка сочетания.
- Локаторы секвенции остаются как в `D01`: шесть пустых (позиция −1), не пустой список. Запись в реестре поправлена.
