## Стори

Нужно сформулировать первый кейс для базовой проверки сценария анализа экспортированной аудиодорожки на основе проекта Elated. Цель: определить инструментарий, который приведет к результату: дорожка проанализирована и готова к нарезке на сэмплы.

Определи какие дорожки нужно взять для анализа и какие сценарии отрабатываются. Добавь для анализа синт Saw Harm.

## Анализ

Это спайк 5 из CLAUDE.md на реальных стемах. Вход: `test-projects/exports/elated/` (64 файла, 48 кГц, 24 бита, настройки спайка 2) и `test-projects/copies/Fuzz - Elated 1.logicx` с исходниками в `Media`. Проект: 120 BPM, 4/4, такт 96 000 отсчётов.

**Дорожка готова к нарезке,** когда есть `analysis.json`: сэмплы с границами в отсчётах, список срабатываний с позицией и громкостью, остаток обратной сборки. Сама нарезка WAV, имена и Export Plan в стори не входят.

**Эталон.** Позиции берутся из `ProjectData` с учётом LOGIC-047 и LOGIC-055, независимо от анализа звука. Для `snare` и `kick` есть второй эталон: исходник из `Media`. Звук в продукте берётся только из экспорта, `Media` служит лишь для проверки.

**Что уже показали прототипы вне репозитория:**

- Поиск атак нашёл 320 из 320 у `kick`, 185 из 185 у `clap`, 136 из 136 у `snare`, 68 из 68 у `Audio 48`, без лишних.
- Сам поиск атак даёт разброс старта до 9 мс. Нужны выравнивание корреляцией, подбор громкости и запас перед атакой.
- Сборка по эталонным позициям из исходника: `snare` −216 дБ, `clap` −213 дБ, `kick` −24 дБ при +0.99 дБ к исходнику. Сборка только из экспорта на реальных файлах не проверялась.
- Весь стек ставится на Python 3.14 (librosa 1.0.0, numpy, scipy, soundfile). В проекте нет `.venv` и файла зависимостей.

**Инструменты:** `probe.py` для эталона и сетки, `soundfile` для чтения, `librosa.onset` для атак, `scipy.signal.correlate` для выравнивания и сходства, `numpy` для громкости и обратной сборки. Определение темпа не нужно: сетка из файла.

**Что мешает:** `probe.py` не применяет папки и считает лишний проход Loop, код расходится с LOGIC-047 и LOGIC-055. Поле длины аудиорегиона (LOGIC-044) и смещение в файле (LOGIC-045) открыты, поэтому код на них не опирается: границы кусков определяются по звуку.

### Вопросы

Нет. Обратная сборка для сценария 7 не требуется: бас играет с разными высотами, для кейгруппы достаточно выбрать ноту-кандидат.

## План

1. **Окружение.** `requirements.txt` с numpy, scipy, soundfile, librosa, pytest, установка в `.venv`.
2. **`probe.py`.** Применить LOGIC-047 и LOGIC-055 в `regions()` и `region_notes()`: Mute и длина папки, Loop по биту `0x200`, конец по `+0x1c`. Добавить команду, отдающую развёрнутые позиции. Проверить на копии 4: 98 нот, это подтвердит LOGIC-050. Обрезанный Loop (LOGIC-051) считать по тому же правилу и сверить с экспортом `Lothar BM`.
3. **`spikes/audio_analysis/analyze.py`.** Вход: WAV и развёрнутая сетка. Шаги: атаки, выравнивание, группировка, подбор громкости, поиск повторов по окнам, обратная сборка, запись `analysis.json`.
4. **`spikes/audio_analysis/test_analyze.py`.** Синтетика с известной структурой на каждый вид сценария.
5. **Прогон 8 дорожек.** Сводная таблица ожидание и факт в `spikes/audio_analysis/CHECKLIST.md`, решение и уточнённые пороги в разделе «Спайк 5» в `docs/spikes.md`.
6. Новые знания о формате оформляются реквестами к базе.

Не входит: нарезка WAV, имена сэмплов, Export Plan, классификация способа экспорта, стеки, полифонические дорожки, сборка проекта MPC, проверка на Live 2.

## Итог ревью

Два раунда. Первый: 6 расхождений, главные это ноты внутри папок и отсутствие громкости в режиме windows, исправлены. Второй: 4 расхождения, тоже исправлены: Loop внутри папки и вложенные папки, тесты на Loop в `region_notes()`, тест остатка на срабатывание, две неточности в документах. Правки второго раунда отдельным ревью не проверялись: 57 тестов зелёные, цифры 8 сценариев не изменились, копия 4 даёт 98 нот, `variant.mid` тоже 98 по замеру ревьюера.

Осталось открытым по существу: окна `LD Saw Harm` с отличием в начале слиты с основной фразой при пороге 0.98, причина не установлена, вынесено в ручную проверку.

## Результат приёмки

Принято пользователем 2026-11-01 с изменённым выводом. Операции анализа работают на реальных дорожках: сетка из проекта, корреляция, выравнивание, подбор громкости. Определение готовности, три режима и остаток как критерий не подтвердились: цель не точное воспроизведение, а перевод с осознанными потерями. Цель записана в CLAUDE.md, сценарии и слабости в `docs/analysis.md`.

Три ручные проверки выше не выполнялись и сняты с приёмки: они проверяли прежний вывод. Вопрос о начале фраз `LD Saw Harm` переходит в сценарий мелодии с вариациями.
